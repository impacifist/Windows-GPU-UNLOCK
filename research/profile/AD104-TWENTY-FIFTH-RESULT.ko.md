# 스물다섯 번째 결과: DMACTL 관측 거부 및 수동 복구

[English](AD104-TWENTY-FIFTH-RESULT.en.md) | [한국어](AD104-TWENTY-FIFTH-RESULT.ko.md)

2026-10-27 테스트25는 기존 PROM/메모리 감사, PROM 저장/읽기 검증/메모리 해제/최종 상태 검사를 완료했습니다. 첫 GSP 배치의5회 읽기 콜백은 모두 상태0으로 반환됐습니다:

| 오프셋 | 값 |
| --- | --- |
| 0 | 0x194000a1 |
| 0x110100 CPUCTL | 0x10 |
| 0x110040 MAILBOX0 | 0 |
| 0x110044 MAILBOX1 | 0 |
| 0x11010c DMACTL | 0xbadf5620 |

FalconBatch는 상위16비트 BADF를 거부하고 EFI_NOT_READY(0x8000000000000006)를 반환했습니다. 이후 experiment-result, manual-power-off-required-no-key-can-resume, handoff-stopped 로그가 있으며 STATUS도 수동 전원 차단 상태를 확인합니다. 읽기가 반환된 뒤 의도적으로 정지한 증거이며 CPU/MMIO 호출 자체가 멈췄다는 증거는 아닙니다. 화면 깜빡임만으로 추가 원인을 판단할 수 없습니다.

첫 배치 나머지 읽기, 두 번째 배치, Shift+V, 디코딩 해제 및 Windows StartImage에는 도달하지 않았습니다. 계획된 추가18회 대신5회만 실행했습니다(전체 Mem.Read262325회). 정지 전 실험이 디코딩을 명시적으로 해제하지 않았습니다. 사용자는 강제 종료 후 Windows 수동 부팅을 보고했으므로 이번 실행의 자동 복구는 실패입니다. 이후 Windows는 RTX4070Ti/드라이버610.88을 감지했으나 계산/복구 부하 테스트는 실행하지 않았습니다.

36개 파일의 원본/복사본 SHA256을 검증했습니다. DIAG427531바이트, SHA256bf2898dc283bf185f08b279a1ecad2c35fede58255f08938aad6a024741da075; STATUS114바이트, SHA2569190572a6f7cde16bc5e0172b9b878c43c456105f90625103a4ac9b959300b29. USB 원본을 유지하며 EFI 해시는 abf77fd008606705ab8e73e0bdc0bfe33b67cbacf35598b14615d4d6d2b11425와 같습니다.

BADF5620은 접근 불가 또는 허용하지 않은 관측으로 거부했지만 하드웨어 의미나 항상 접근 불가인지 입증하지 않습니다. 메일박스0은 준비 상태를 뜻하지 않습니다. 센티널 검사를 완화하거나 레지스터 제어 쓰기/리셋/업로드/실행/언락을 수행하지 않았습니다. 체크리스트는15/26(58%)입니다. 현재 USB를 반복 실행하거나 Shift+V를 복구 명령으로 사용하지 마십시오. DMACTL 접근 조건을 조사한 뒤 다음 후보를 별도 검토해야 하며 이번 결과 업데이트에서 새 후보를 스테이징하지 않았습니다.
