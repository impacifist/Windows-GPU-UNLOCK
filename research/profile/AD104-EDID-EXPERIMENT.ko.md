# AD104 EDID 수명 주기 실험 제안

[English](AD104-EDID-EXPERIMENT.en.md) | 한국어

상태: `b45ddd6`에서 구현하고 호스트 시험 및 네이티브 빌드를 완료했다. 실제
펌웨어 동작은 아직 시험하지 않았다. [일곱 번째 부팅 지침](AD104-SEVENTH-BOOT.ko.md)을
참고한다. 운영자는 준비 전에 검증되지 않은 복구 경계를 명시적으로 수락했다.

## 질문과 단일 작업

고정한 IMG08 바인딩이 공유 포인터 역할과 GPU의 현재 PCI 상태를 유지하면서
탐색한 GOP 자식의 EDID Discovered 관계만 해제할 수 있는가? 후보 작업은
정확히 한 번의 `DisconnectController(gop_child, img08_binding_handle, NULL)`이다.
주소는 저장된 로그가 아닌 새 탐색으로 구해야 한다. PCI 컨트롤러, 콘솔,
모든 드라이버, IMG29 또는 null-image 바인딩을 대상으로 삼으면 안 된다.
Stop을 직접 호출하지 않는다. 펌웨어 드라이버 모델의 조정과 결과도 실험 대상이다.

정적 분석에서는 EDID 분기가 IMG08 RVA `546a`의 바이트를 지우고 EDID 관계를
닫을 것으로 예상한다. 이 바이트의 전체 의미는 아직 모른다. 펌웨어는 보이는
분기보다 더 많은 동작을 할 수 있다. 성공 반환이나 그래프 일치만으로 지연된
영향이 없음을 입증하지는 못한다.

## 필수 허용 조건과 증거

구현은 다음 조건을 함께 유지해야 한다.

1. 정확한 GPU 식별 정보/BDF, 네 코드 지문과 바인딩, null 바인딩, 관련 활성
   관계 여덟 개, 공유 관측 값 `1/1/1`, 전체 PCI 구성, BAR 설명자, 현재 속성
   `718` 및 지원 값 `1b77b`를 확인한다. 호출 직전 두 번의 수집이 일치해야 한다.
   토폴로지 일치만으로 작업을 허용하지 않는다.
2. 정확한 Windows 부팅 이미지와 준비한 인계 경로를 확인한다. 이미지 로드의
   성공은 준비 단계이며 변경 후 실제 실행의 증거가 아니다.
3. 호출 전에 제한 시간이 있는 실제 사용자 키보드 입력을 확인한다. 포인터의
   안정성만으로는 부족하다. 임의의 입력 키를 저장하지 않고 확인 성공/상태만
   기록한다. 시간 초과나 예상과 다른 입력은 호출을 취소한다.
4. DisconnectController에 들어가기 전에 USB에 사전 상태와 일회성 실행 의도를
   쓰고 flush 성공을 확인한다. 호출 전에 시도 표시를 남긴다. 기록 실패 시
   호출하지 않는다. 콜백 자체가 멈출 수 있으며 폴링 제한 시간은 콜백을 중단하거나
   복구를 보장할 수 없다.
5. 오류를 포함하여 콜백이 반환하면 상태, 그래프, 공유 값, 전체 PCI 구성,
   리소스/속성 조회와 콘솔 식별 정보를 독립적으로 수집한다. 콜백 오류가 나도
   사후 검사를 생략하지 않는다.
6. 제한 시간이 있는 실제 키보드 입력을 다시 확인한다. 모든 사후 조건과 결과의
   영구 기록을 확인한 뒤에만 준비된 Windows 인계를 고려한다. 입력 확인 실패는
   재시도 허가가 아니다.

각 입력 확인은 60초 분량의 폴링 예산이며 절대 실행 제한 시간이 아니다.
ReadKeyStroke, OutputString, Stall 또는 다른 펌웨어 콜백 자체가 멈출 수 있다.
안내 전에 최대 32번 읽기로 대기 입력을 비운다. 전에는 대문자 `E`, 후에는
대문자 `V`만 허용한다. 입력한 키 자체를 증거 로그에 저장하지 않는다.

예상 사후 상태는 관련 활성 관계 일곱 개다. IMG08의 EDID BY_DRIVER 관계만
사라진다. 공유 바이트는 0이 되고 두 포인터 관계와 카운트 `1/1`은 유지된다.
PCI 소유자, 텍스트/GOP 소비자, 콘솔/입력 식별 정보, 전체 PCI 구성, BAR 설명자,
속성도 유지된다. 별도의 사후 상태 검사기가 필요하다. 현재 여덟 관계 사전 검사가
일곱 관계 그래프를 거부하는 것은 올바르며 검사를 느슨하게 바꾸면 안 된다.

호스트 모의 시험은 잘못된 식별 정보/지문/그래프, 오래되거나 바뀐 관측,
입력 부재와 시간 초과, 의도 기록/flush 실패, 성공 및 부분 변경을 동반한 콜백
오류, 사후 검사/기록 실패, 예상 밖 추가 관계 해제, 재시도를 포함해야 한다.
모의 시험 성공은 실제 펌웨어 동작이나 복구 가능성을 입증하지 못한다.

## 실패 경계와 남은 작업

한 번만 시도한다. 추측에 따른 재연결, ConnectController, 속성 복원, 소유자
해제, MMIO, unlock 또는 자동 재부팅은 이 실험에 포함하지 않는다. 콜백 오류는
이미 상태가 변경되었을 수 있음을 뜻한다. 관측 부재, 예상 밖 전이, 입력 손실,
기록 실패 시 추가 드라이버 작업과 자동 Windows 인계를 차단해야 한다. 쓸 수 있는
증거를 보존하고 수동 복구를 기다린다. 콜백이 멈추면 그 기록도 불가능할 수 있다.

화면/입력 손실, 펌웨어 정지, Windows 부팅 실패, 수동 전원 차단 및 USB 제거 후
일반 Windows Boot Manager 선택이 필요할 수 있다. 전원을 다시 켜는 것은 복구
시도이지 검증된 보장이 아니다. 이 호스트에는 내장 GPU가 없다. 영구 쓰기를
의도하지 않는다는 이유만으로 확실한 복구를 약속하면 안 된다. 첫 변경 테스트
전에 운영자가 이 경계를 이해해야 한다.

결과가 완전히 일치해도 이 EDID 수명 주기 전이만 입증한다. PCI 소유자 해제,
제한적 디코딩 활성화, cold-entry/보호 메모리 검사, unlock 트랜잭션, 통제된
Windows 작업 검증은 별도 단계로 남는다.
