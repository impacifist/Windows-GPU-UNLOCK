# 두 번째 AD104 부팅 결과: ROM 메타데이터 제공 확인

[English](AD104-SECOND-RESULT.en.md) | 한국어

사용자가 2026-10-26에 두 번째 테스트 후 돌아왔습니다. USB EFI의 SHA-256은
준비한 메타데이터 전용 산출물과 일치했습니다.
`92e038ddf621a227ac37c7afba2d589272d0a39ad431ad769c5f1f8730f6792d`
새 캡처 파일 33개를 별도의 비공개 호스트 보관 위치로 복사하고 각 SHA-256이
USB 원본과 일치함을 확인했습니다. USB 원본은 변경하지 않았습니다.

대상은 `0000:0b:00.0`의 `10de:2782`, 서브시스템 `1462:5132`, 클래스/리비전
`030000a1`로 유지되었습니다. 핵심 관찰값은 다음과 같습니다.

```text
ad104-metadata-only=1 rom-pointer-present=1 rom-bytes=0x0000000000024a00 command=0x0007 memory-enabled=1 bus-master-enabled=1
```

펌웨어가 null이 아닌 PCI I/O ROM 포인터와 150,016바이트를 보고합니다.
프로브는 포인터를 역참조하거나 ROM 내용을 복사하지 않았습니다. 확인된 것은
보고된 메타데이터뿐입니다. 읽기 가능성, 유효한 옵션 ROM 형식, 전체 이미지
범위 및 실제 PROM과의 동일성은 아직 알 수 없습니다. 버스 마스터링은 여전히
활성화되어 있으며 기존 심층 캡처 보호 조건은 변경하지 않았습니다.

`ad104-metadata-only-no-mmio`, `capture-complete=0`, `EFI_NOT_READY`는 이
모드의 예상 결과입니다. ROM 읽기를 시도했다가 실패했다는 뜻이 아닙니다.
로그는 393,832바이트이며, 드라이버 이미지 스냅샷 32개의 고유 해시는 25개입니다.
오프라인 분석기는 PCI 소유자를 IMG29 및 GOP 자식에, 텍스트 출력 콘솔 계층을
IMG14에 다시 연결했습니다. 이 관계는 관찰이며 드라이버 해제 허용이나 안전한
해제 순서의 증거가 아닙니다.

이번 테스트는 ROM 바이트나 GPU 레지스터를 읽거나 언락 또는 드라이버 해제를
시도하지 않았습니다. 로그는 Windows 시작 호출 전에 끝나므로 그 호출을 통한
자동 복귀를 입증하지는 않습니다.

다음으로 유용한 실험은 별도로 검토된 제한적 펌웨어 ROM 버퍼 복사입니다.
형식, 길이, 장치 ID 및 일관성 검사가 필요하며 BME를 그대로 두고 BAR MMIO를
사용하지 않아야 합니다. 이번 결과 확인 작업에서는 세 번째 EFI를 준비하거나
USB에 배치하지 않았습니다.
