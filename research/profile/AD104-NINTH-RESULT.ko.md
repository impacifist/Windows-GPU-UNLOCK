# 아홉 번째 AD104 부팅: 제공자 캡처 및 텍스트 해제 관측

[English](AD104-NINTH-RESULT.en.md) | 한국어

결합한 두 단계가 성공했다. `PCDPROD.BIN`은 11,840바이트이며 SHA-256이 펌웨어의
안정 복사 기록과 일치한다.
`362a8b2d6e3b9d0d231d47b84cae709858a811b06e6a10e00d584a24154deeef`.
실행 코드 범위는 RVA `0x2a0`, 길이 `0x236d`, SHA-256
`cb64fe58020cf7512de99c86d8284baca00dd679109680ea1af371081e3b6367`이다.
재배치 레코드를 해석한 결과 해당 코드 범위의 대상은 없다. RVA `0x4f4`의
GetBool은 크기 1로 헬퍼 `0x1120`을 호출하고 반환 주소의 바이트를 읽는다.
Boolean 접근자 형태를 뒷받침하지만 제공자/데이터베이스 헬퍼의 전체 검토는 아니다.

텍스트 연결 해제는 성공을 반환했다. 두 사후 수집과 최종 검사는 여섯 관계,
IMG08 공유 값 `1/1/1`, PCI/BAR/속성 및 GOP 모드 불변에 일치했다. IMG14 목록은
레코드 하나에서 빈 목록이 되었고 캐시 PCD는 현재 인터페이스가 되었다. 실제
입력 확인 두 번도 통과했다. 네 개의 전체 256바이트 PCI 구성은 동일하다.
command `0007`, 속성 `718`, 지원 `1b77b`가 유지되므로 cold GPU 상태나 unlock은 아니다.

34개 파일을 USB/호스트 해시 일치로 보존했다. 로그는 404,006바이트이며 SHA-256은
`3f61d24ca55da4d79e58790c035db5ec848ad3220c5b8ecbd7a4d4834e6eecbb`이다.
USB EFI는 `2e2cb3069992b076db3e84a0ff9ca266230ab4d107f0cd96866547907f18de7d`와 일치한다.
사용자 복귀 후 Windows는 드라이버 `610.88`, VBIOS `95.04.31.00.f0`와 예상한
GPU/BDF를 확인했다. 현재 드라이버 사용 가능성이며 StartImage 이후 추적이나
추가 해제의 복구 보장은 아니다. [정리된 증거](ad104-ninth-boot-evidence.json)를
참고하며 원본 자료는 비공개로 유지한다.

다음 대상은 텍스트 제거 후의 IMG17 GOP 소비자다. Stop 정적 분석은 SimpleTextOut과
동반 프로토콜 `e1e4a857-c970-4075-a4da-e9c41b69adfc` 제거, GOP open 닫기 및
텍스트 인터페이스/모드/추가 할당 해제를 보여준다. 여러 정리 반환 값을 무시하고
성공을 반환한다. Stop 본문에 직접 SetMode/Blt 호출은 없지만 펌웨어를 통한 영향은
가능하다. 향후 테스트는 두 프로토콜 제거와 여섯 관계에서 다섯 관계 전이를 모두
검증하고 호출 후 저장된 자식 텍스트 인터페이스/모드를 역참조하면 안 된다.
PCI 소유자와 GOP 인터페이스는 별개이며 유지하는 대상이다.
