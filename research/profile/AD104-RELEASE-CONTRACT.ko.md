# AD104 해제 계약: 호스트 모델 전용

[English](AD104-RELEASE-CONTRACT.en.md) | 한국어

[다섯 번째 캡처](AD104-FIFTH-RESULT.ko.md)에서 현재 속성 `0x718`, 지원 속성
`0x1b77b`, command `0007`을 확인했습니다. 정적 Stop 분석은 가능한 Disable
마스크 `0x718`을 예측합니다. 이 호스트에서 성공한 드라이버 해제나 이후 상태를
관찰한 것은 아닙니다.

`lifecycle-model.py`는 탐색적 호스트 전용 계약을 정의합니다. EFI 어댑터가 없고
EFI 빌드에 연결되지 않으며 런타임 권한을 부여하지 않습니다. 구성과 네 가지
그래프 역할은 합성 테스트 자료이며 OEM 프로필이나 실제 전체 프로토콜 그래프의
해석이 아닙니다.

## 평가할 제안 순서

| 단계 | 합성 예상 상태 | 실패 대응 |
| --- | --- | --- |
| 초기 관찰 | 정확한 장치/BDF/소유자 지문, command 7, 속성 `0x718`, 예상 그래프, 키보드와 고정 부팅 이미지 | 상태 변경 시도 0회 |
| 텍스트 소비자 콜백 | 해당 추상 연결만 제거, 구성/속성 유지 | 중단, 재시도/인계 없음 |
| 그래픽 소비자 콜백 | 해당 추상 연결만 제거, 구성/속성 유지 | 중단, 재시도/인계 없음 |
| PCI 소유자 콜백 | 예상 소유자/자식 연결 없음, 예측 command 0 및 속성 0, 나머지 구성 유지 | 중단, 재시도/인계 없음 |
| 제한된 디코딩 활성화 | 기존 I/O와 메모리 마스크 `0x300`만 활성화, 예측 command 3 및 속성 `0x300` | 중단, 재시도/인계 없음 |

소유자 콜백 뒤 command 0 / 속성 0은 의도적으로 엄격한 **예측**이며 확인된
하드웨어 동작이 아닙니다. 정확한 검사는 무해한 변화도 거부할 수 있으며 거부가
손상의 증거는 아닙니다. 콜백 오류 전에 부분 변경이 있었을 수 있으므로 오류를
변경 없음으로 취급하지 않습니다. 각 콜백 전에 시도를 기록하며 자동 롤백이나
재시도를 하지 않습니다.

성공한 모의 콜백마다 새 관찰이 필요합니다. 새 세대, PCI 구성 256바이트 전체, BAR 설명자,
속성, 지원 마스크, BDF, 그래프, 키보드, 고정 부팅 이미지 및 수집된 지문의
출처를 검사합니다. 추가 연결, 부분 종료 또는 입력 손실 시 다음 단계로 진행하지
않습니다. 원자적 펌웨어 스냅샷이 아니며 호스트 구현은 실제 그래프 검증기가 아닙니다.

디코딩 단계는 **원래 상태의 복원이 아닙니다**. BME(`0x400`)나 VGA(`0x18`)를
활성화하거나 BAR를 수정하거나 GPU를 리셋하거나 펌웨어를 실행해서는 안 됩니다.
콘솔 소유권이나 디스플레이 기능도 복원하지 않습니다. 기존 GA102 디코딩 정책은
변경하지 않으며 BME가 켜진 AD104에 몰래 재사용하지 않습니다.

## 검증과 남은 조건

`python -m unittest discover -s research/profile -p 'test_*.py'`로 실행합니다.
Python 테스트 25개가 통과했습니다. 새 모델 테스트는 각 콜백 실패를 주입하고
성공 후 오래된 관찰, 부분/예상 밖 연결, 키보드 손실, 부팅 이미지 변경, 구성/BDF/
지원 마스크/BAR 설명자 변경 및 예상 밖 BME/VGA 상태를 거부합니다. 초기 command의
추가 비트도 거부합니다. 콜백 예외나 시도 후 캡처 예외는 상태 불명 결과로 중단하며
초기 캡처 예외에서는 시도하지 않습니다. 디코딩 콜백 오류도
해제 콜백 오류와 마찬가지로 중단합니다. 모든 합성 상태가 일치해도 Windows,
언락 및 런타임 허용은 false입니다.

상태를 변경하는 EFI 준비 전에 필요한 작업은 다음과 같습니다.

- IMG29 내부 Stop을 가진 null 이미지 바인딩, 공유 소비자 및 레거시 서비스
  의존성을 포함한 완전한 캡처별 그래프 모델.
- 네이티브 NVIDIA 해제 프로필의 이름만 바꾸는 대신 각 콜백의 소유권 검증과
  좁게 고정된 런타임 사전 검사.
- 해제 후 GPU 콜드 상태 검사 정의. 디코딩 전환 성공만으로 WPR2 상태나 언락
  허용 조건을 확인할 수 없습니다.
- 부분 Stop, 디스플레이/입력 손실, 디코딩 활성화 실패에 대한 현장 대응 및
  해제 후 Windows 로더 실행 가능성의 별도 검증.

이 모델 작업에서는 Stop, DisconnectController, 속성 변경, GPU MMIO, 언락,
재부팅 또는 USB 교체를 수행하지 않았습니다. USB에는 다섯 번째 질의 진단이
그대로 있으며 이를 반복해도 이 계약을 테스트하지 않습니다. 남은 오프라인
작업에 새 EFI 부팅은 필요하지 않습니다.
