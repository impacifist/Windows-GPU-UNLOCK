# AD104 텍스트 수명 주기: 정리 경로의 GOP 호출

[English](AD104-TEXT-LIFECYCLE.en.md) | 한국어

일곱 번째 부팅의 비공개 IMG14 로드 메모리 스냅샷을 정적으로 분석했다.
콜백, 추출한 펌웨어 또는 새 EFI 테스트는 실행하지 않았다. 고정한 Stop 진입점은
RVA `0x11e0`이다. 자식 수가 0인 분기는 자식 정리 없이 성공을 반환하므로 이 반환만으로
해제를 입증할 수 없다. 자식이 하나인 분기는 기록된 콘솔 자식을 요구하고 Simple
Text Output 관계를 닫으며 목록 레코드를 제거하고 메모리를 해제한다.

## 두 관계 제거 외의 동작

Stop은 RVA `0x335c` 헬퍼를 호출하며 이 헬퍼는 HandleProtocol로 GOP를 얻는다.
저장 이미지에서 별도로 해석한 RVA `0x6000`의 GUID는
`9042a9de-23dc-4a38-96fb-7aded080516a`이다. 헬퍼는 버퍼를 할당/복사하고
RVA `0x3453`에서 인터페이스 오프셋 `0x8`의 GOP SetMode를 호출할 수 있다.
인수는 현재 `Mode->Mode`이다. 같은 모드를 요청하더라도 SetMode 호출이므로
읽기 전용 조회나 화면 상태에 영향이 없는 동작으로 분류하면 안 된다.

이 분기의 제어 조건을 API 수준에서 확인했다. RVA `0x4aac` 헬퍼는 GUID
`11b34006-d85b-4d0a-a290-d5a571310ef7`의 프로토콜을 찾고 캐시한다.
저장소 EDK2 `Protocol/Pcd.h`의 `PCD_PROTOCOL_GUID`와 일치한다. RVA `0x343d`의
간접 호출은 오프셋 `0x30`과 토큰 `0x4ac`를 사용한다. 로컬 프로토콜 구조에서 이
슬롯은 `GetBool`이며 Boolean 반환이 SetMode 경로를 제어한다. 이 플랫폼 토큰의
의미 있는 이름과 실제 값은 아직 확인하지 못했다. 다른 펌웨어의 토큰 이름을
추정하거나 분기를 막으려고 값을 쓰면 안 된다. 저장된 캐시 인터페이스 포인터는
0이지만 LocateProtocol 실패 또는 이후 getter의 false 반환을 뜻하지 않는다.

Stop은 두 CloseProtocol의 반환과 헬퍼 결과를 무시한다. 최종 반환이 앞선 모든
동작의 성공이 아니라 FreePool 결과를 반영할 수 있다. 독립적인 사후 조건이 필요하다.

스냅샷의 RVA `0x7160`은 목록 레코드 수 `1`을 보여주며 첫/마지막 포인터가 일치한다.
RVA `0x6f60`의 캐시 핸들은 로그의 콘솔 핸들과 일치한다. 힙 레코드 자체는 이미지
스냅샷 밖에 있어 역참조하거나 모든 필드를 확인하지 않았다. 절대 주소는 생략했다.

## 다음에 필요한 증거

실제 텍스트 해제 제안 전에 ConOut/StdErr 인터페이스와 콜백 소유자, 자식 GOP의
SetMode 콜백 및 모드/프레임버퍼 상태, 플랫폼 조건의 동작을 확인해야 한다.
기존 증거와 범위를 제한한 관측을 우선한다. 읽기로 답할 질문에 저장 이미지를
실행하거나 Stop을 호출하면 안 된다. 프로토콜 구조는 API를 식별할 뿐 OEM
구현의 동작을 보장하지 않는다. 메타데이터 조회만으로 해제나 unlock을 허용하지 않는다.

향후 테스트는 호출 전 실행 의도를 기록하고 시도 후 OutputString 호출 없이
동작해야 한다. EDID를 유지한 독립적인 새 부팅에서 여섯 관계의 별도 예상 상태,
모드/리소스/구성 영향 검사, 실제 입력 증거 및 검토된 정지/Windows 인계 경로가
필요하다. EDID 성공으로 이 대상의 복구 가능성을 입증하지는 못한다. 이번 분석은
텍스트 또는 PCI 소유자 해제 EFI를 준비하지 않았다.

후속 구현: 운영자가 빠진 PCD 제공자 캡처와 텍스트 해제를 같은 부팅에서
시험하도록 요청했다. [아홉 번째 부팅 계약](AD104-NINTH-BOOT.ko.md)은 같은 실행의
제공자 일관성 검사와 조용한 사후 입력 절차로 이 순서를 구현한다. 새로 캡처한
제공자의 사전 독립 검토를 제공하는 것은 아니다.
