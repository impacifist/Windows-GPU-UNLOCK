# 스물여섯 번째 후보: 메일박스 전용 기준 상태

[English](AD104-TWENTY-SIXTH-BOOT.en.md) | [한국어](AD104-TWENTY-SIXTH-BOOT.ko.md)

빌드/호스트 검사 완료, 실제 테스트26 실행 전입니다. 승인된 테스트25 읽기 집합의 부분집합이며 DMACTL0x11010c를 완전히 제외합니다. BADF를 허용하는 방식이 아니며 해당 접근 제한의 원인은 미해결입니다. 기존 테스트25 모드와 센티널 정지는 재현 가능하게 유지합니다.

기존 테스트24 캡처/RAM 조립 후8회씩 두 배치로 읽습니다:
`0, 0x110100, 0x110040, 0x110044, 0x82381c, 0x823820, 0x625f04, 0`.
칩 시작/종료, CPUCTL, MAILBOX0/1, SS0/SS1, VGA_BASE입니다. 승인된25 외의 GPU 주소/작업은 없으며 추가18회에서16회로 줄어 성공 시 전체 Mem.Read262336회입니다. 거부된 DMACTL 접근 없이 메일박스 재현성과 PROM 후 선택자 안정성을 관측하고 기존 디코딩 해제/Windows 복귀를 확인합니다. 엔진 준비나 SS1/VGA 진입 문제 해결을 뜻하지 않습니다.

전송/모두1/BADF/칩/중요 상태/메서드/로그/소유권 검사를 유지합니다. CPUCTL/SS0/SS1/VGA는 기존22회 읽기의 두 번째 배치와 같아야 하며 메일박스 변화만으로는 거부하지 않습니다. 각 RAM 배치/로그 전후 전체 상태를 검증하고 읽기 중 할당/파일 호출은 없습니다. 리셋/인터럽트 확인/DMA 시작/GPU 제어 쓰기/BME/VGA 활성화/펌웨어 업로드·실행/언락/자동 롤백을 추가하지 않습니다. 실패 시 여전히 정지하고 수동 전원 차단이 필요할 수 있습니다. 기존 승인은 축소된 읽기 집합을 포함하지만 복구를 보장하지 않습니다.

회귀 모의 테스트는25의9개/26의8개 모드, 정확한 주소/횟수, 모든 전송 오류 위치, 메일박스BADF5620 거부, 모두1, 중요 상태/메서드/소유권/로그 오류 및 메일박스 변화를 확인합니다. 센티널 규칙은 유지됩니다. AMD64/가져오기 없음 EFI66,560바이트, SHA256:
`9a0a77857d8453e294a6fce8b01565b5ac26bd6d10ad578acde770e3afb9c6cc`.
매니페스트 mailbox-only=true, 추가읽기16, CanReadDmaControl=false, 펌웨어실행/언락=false입니다.

작업 저장/완전 종료/10초/UEFIUSB/Shift+G 한 번.10초 후 Shift+V를2초마다 최대3분 누릅니다. 보호 정지는 키로 재개할 수 없습니다.10분 후 Windows가 없으면 전원 차단/USB 제거/정상 Boot Manager를 선택합니다. 이번 실행의 복구는 미검증입니다. 한 번만 실행하고 재시도 전 캡처를 보존합니다. 스테이징 전 테스트25 원본/기존EFI를 보존·검증해야 합니다.
