# 아홉 번째 AD104 부팅: PCD 캡처 후 텍스트 연결 해제 한 번

[English](AD104-NINTH-BOOT.en.md) | 한국어

운영자는 부팅 한 번을 줄이기 위해 빠진 PCD 지문 캡처와 텍스트 해제 실험을
결합하도록 요청했다. 먼저 캡처하고 캡처 및 새 검사가 성공할 때만 텍스트 해제를
한 번 허용한다. EDID/PCI 소유자 해제, 속성 쓰기, GPU MMIO, unlock은 없다.

## 캡처 및 허용 조건

기준 출력 관측을 먼저 수행한다. 유일한 로드 제공자가 펌웨어 파일 GUID
`80cf7257-87ab-47f9-a3fe-d50b76d89541`, 크기 `0x2e40`, boot-services 코드
타입과 GetBool RVA `0x4f4`에 일치해야 한다. GetBool/GetNextToken/GetSize는
해당 PE 이미지의 실행 섹션 안에 있어야 한다. 로드 이미지를 RAM에 복사하고
파일 작업 전후 바이트와 프로토콜 식별 정보를 재확인한다. 새 비공개
`PCDPROD.BIN`에 전체 write/flush/close를 확인하며 저장하고 SHA-256을 기록한다.
기존 파일, 모호한 제공자, 잘못된 PE, 변경된 바이트, root/file 별칭은 거부한다.
SPI 플래시나 원래 펌웨어 파일은 읽지 않는다. 캡처 이미지를 새 이미지로 로드하거나
실행하지 않는다. 일반 PCD 조회는 설치된 실제 프로토콜을 통해 계속 수행한다.

같은 실행의 제공자 해시, 인터페이스와 세 메서드는 텍스트 검사 내내 일치해야 한다.
이는 저장 바이트와의 일관성이며 **사전 독립 코드 검토나 제공자 인증이 아니다**.
새 덤프의 오프라인 검토는 결합 실행 이후에 한다. 새로 계산한 해시를 이미
신뢰된 지문으로 취급하지 않는다.

안내 전과 호출 직전에 정확한 GPU/코드/바인딩, 여덟 관계, IMG08 공유 상태
`1/1/1`, 전체 PCI 구성, BAR 및 속성 `718`/지원 `1b77b`를 요구한다. 새 PCD
열거/크기/GetBool 검사는 false를 반환해야 한다. GOP 모드/인터페이스/정보/
프레임버퍼 메타데이터는 일치하고 조회 전후 안정적이어야 한다. 실험 자체는
SetMode를 호출하지 않지만 native Stop에는 자체 화면 영향이 있을 수 있다.
일반 로그와 드라이버 덤프 32개에 `PCDPROD.BIN`을 더해 총 34개 파일을 예상한다.

IMG14의 로드 목록은 레코드 수 하나, 같은 비-null 첫/마지막 포인터, 예상한
캐시 콘솔 핸들을 가져야 한다. 캐시 PCD는 없거나 현재 인터페이스여야 한다.
고정한 이미지 내부의 제한된 필드만 읽으며 힙 레코드는 역참조하지 않는다.
일회성 시도 전에 실행 의도를 기록하고 flush해야 한다.

## 단일 전이와 조용한 완료

수명 주기 호출은
`DisconnectController(discovered_gop_child, exact_img14_binding, NULL)` 하나다.
애플리케이션은 호출 전에 콘솔 출력을 차단하고 오류/정지/Windows 경로에서도
유지한다. 시도 이후 콘솔 출력을 하지 않으며 보호된 Say 호출은 OutputString 없이 반환한다. 이 제한은
애플리케이션에 적용되며 펌웨어나 Windows 내부 호출을 통제하지는 못한다.

콜백의 성공/오류와 관계없이 독립 사후 상태를 두 번 수집한다. 예상 상태는
텍스트 두 관계만 사라짐(여덟 개에서 여섯 개), EDID와 두 포인터 역할 유지,
IMG08 `1/1/1` 및 PCI/BAR/속성/GOP 상태 불변이다. 텍스트 목록은 비워지고
캐시 PCD는 현재 제공자와 일치해야 한다. 헬퍼/할당 실패는 Stop이 성공을 반환해도
거부를 일으킬 수 있다. 제공자 해시와 false 조건도 유지되어야 한다. 사후 상태
일치만으로 일시적 SetMode 또는 다른 화면 동작이 없었음을 입증할 수는 없다.

사후 검사가 성공하면 화면 안내 없이 실제 입력을 확인한다. 미리 대기한 키는
버리고 이후 새 대문자 `V`를 요구한다. 새 상태 수집, 결과 기록과 파일 닫기도
성공해야 Windows로 인계한다. 실패 시 연결 해제 전이라도 재시도, 재연결, 복원,
재부팅 또는 펌웨어 BootOrder 대체 부팅 없이 정지한다.

## 운영자 지침

1. 작업을 저장한다. USB를 연결하고 `shutdown /s /t 0` 실행 후 전원이 꺼지면
   10초 기다린다. ASUS Delete → F8 → **UEFI: USB DISK 2.0**(8GB)을 선택한다.
2. 캡처와 첫 안내를 기다린다. **Shift+T**를 한 번 눌러 텍스트 해제 한 번을
   허용한다. 다른 키나 시간 초과는 실험을 정지한다.
3. `T` 후 5초 기다리고 **Windows가 시작될 때까지 Shift+V를 2초마다 짧게
   누른다**. 최대 1분까지 시도하고 키를 누른 채 유지하지 않는다. 두 번째
   안내는 없으며 화면이 꺼지거나 이전 안내가 그대로 남을 수 있다.
4. 정지하거나 Windows가 5분 안에 복귀하지 않으면 전원을 끄고 USB를 제거한 뒤
   일반 Windows Boot Manager를 선택한다. 한 번만 부팅하고 다음 실행 전에 보존한다.

화면/입력 손실, 펌웨어 정지, Windows 복귀 실패가 가능하다. 내장 GPU가 없으며
이 대상의 복구는 검증되지 않았다. 입력은 60초 분량의 폴링 예산이지만 펌웨어
콜백 자체가 멈출 수 있다. 5초는 운영자 대기 지침이지 콜백 실행 시간 보장이
아니다. 반복 입력은 사후 검사가 끝나기 전 유일한 응답을 잃는 문제를 피한다.

구현 `908be19`, 네이티브 EFI 41,984바이트, SHA-256
`2e2cb3069992b076db3e84a0ff9ca266230ab4d107f0cd96866547907f18de7d`.
빌드 옵션은 `-Ad104Msi -Ad104Metadata -Ad104Resources -Ad104Preflight
-Ad104OutputObservation -Ad104PcdCapture -Ad104TextTest -WindowsMbr`이다.
CanDetach/CanCapturePcdProducer는 true, CanUnlock/CanReadGpuMmio/
CanDereferenceRomImage/WritesFirmwareVariables는 false, HardwareTested는 false다.
AMD64 PE 검사는 import/IAT/delay import 없음과 NX/dynamic base를 통과했다.
RAM 검사 통과 수는 제공자 52, 화면 29, 텍스트 수명 주기 139, 조용한 인계 21이며
기존 검사와 Python 31개도 통과했다. 잘못된 빌드 조합 26개를 거부했다.
이는 모의 환경의 소프트웨어 동작이며 실제 텍스트 해제 성공은 아니다.
준비 전에 여덟 번째 캡처/EFI를 호스트와 USB에 보존한다.
