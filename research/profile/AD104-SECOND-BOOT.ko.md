# 두 번째 AD104 테스트: 펌웨어 ROM 메타데이터

[English](AD104-SECOND-BOOT.en.md) | 한국어

사용자가 현장에 있는 이번 테스트는 정확한 MSI AD104 장치의 PCI I/O에서
펌웨어 제공 ROM 버퍼 포인터와 크기를 노출하는지 확인합니다. 포인터 존재 여부만
기록하며 주소나 내용은 기록하지 않습니다. 기존 소유권/이미지 캡처도 실행되어
레거시 비디오 프로토콜 그래프를 관찰할 수 있습니다.

`build-probe.ps1`에 `-Ad104Msi -Ad104Metadata -WindowsMbr`를 사용합니다.
출력: `internal-boot/boot/build/probe-ad104-metadata/BOOTX64.EFI`.
구현 `6dec9ce`에서 빌드한 네이티브 산출물은 20,992바이트이며 SHA-256은
`92e038ddf621a227ac37c7afba2d589272d0a39ad431ad769c5f1f8730f6792d`입니다.
PE 검증을 통과했습니다: AMD64 EFI 애플리케이션, imports/IAT/delay imports
없음, NX 및 dynamic base 활성화. 매니페스트는 메타데이터 전용 모드와 GPU
MMIO 비활성화를 명시합니다. 이는 빌드 검증이며 실제 부팅 결과가 아닙니다.

메타데이터 표시 전에 정확한 PCI/서브시스템/리비전을 검사합니다. BAR 리소스
검사, PROM 할당, GPU MMIO 및 ROM 포인터 역참조 전에 반환합니다. 드라이버
해제, BME 해제, 펌웨어 업로드 및 언락은 수행할 수 없습니다.
`ad104-metadata-only-no-mmio`, `capture-complete=0`, `EFI_NOT_READY`는 의도된
결과이며 보호 조건 우회를 요구하는 오류가 아닙니다. BAR0가 0이면 기존 호출자가
거부하므로 ROM 제공 여부는 알 수 없습니다. 포인터/크기는 검증되지 않은
펌웨어 필드이며 읽기 가능성, 완전한 ROM 내용 또는 실제 PROM과의 동일성을
입증하지 않습니다.

호스트 검사 통과: 기존 AD104 151개, 메타데이터 24개(잘못된 포인터 값 1,
최대 보고 크기, 다른 장치 ID 포함), MBR 66개, GPT 4개, 거부된 컴파일 조합
17개. Python 테스트 15개도 통과했습니다.

## 부팅 전후

첫 부팅 파일 전체와 기존 EFI를 보관한 뒤 교체합니다. USB를 포맷하거나 내부
부팅 설정을 바꾸지 않습니다. 기존 덤프를 덮어쓰지 않으므로 활성
`RTX3090-UNLOCK` 디렉터리는 비어 있어야 합니다. 이 기존 이름은 3090 프로필을
선택한다는 뜻이 아닙니다.

작업을 저장하고 캡처 USB를 연결한 상태에서 `shutdown /s /t 0`을 실행합니다.
완전히 꺼진 뒤 10초 기다립니다. Delete로 ASUS BIOS에 들어가 F8 부팅 메뉴에서
8GB USB DISK 2.0의 UEFI 항목을 선택합니다. 테스트 키 입력은 필요하지 않습니다.
이후 고정된 Windows Boot Manager 시작을 시도합니다. 4분 안에 Windows로
돌아오지 않으면 전원을 끄고 USB를 제거한 뒤 일반 Windows Boot Manager로
부팅합니다. 자동 복귀는 보장하지 않습니다.

복귀 후 USB를 다시 부팅하지 마십시오. 새 `DIAG00.TXT`와 이미지 전체를
보존합니다. `ad104-metadata-only=1 rom-pointer-present=... rom-bytes=...`를
확인합니다. 두 값이 모두 0이거나 불일치하거나 관찰 자체가 없어도 유효한
결과입니다. 메타데이터가 없다고 물리 ROM이 없다고 판단하지 않습니다.
포인터가 있고 크기가 타당하면 별도로 제한된 버퍼 캡처를 설계할 근거가 될 뿐,
언락 실행 근거는 아닙니다. 이번 테스트는 ROM 버퍼를 복사하지 않습니다.
