# 열두 번째 AD104 시험: 소유자 자식 Stop 직접 호출

[English](AD104-TWELFTH-BOOT.en.md) | 한국어

상태: 2026-10-27 실제 시험 성공; [결과](AD104-TWELFTH-RESULT.ko.md)를 참조하세요. 입증된 텍스트/
GOP 소비자/EDID 순서 뒤에 네 번째 단계를 추가합니다. 정확히 IMG29 바인딩의
`Stop(binding, gpu, 1, &child)`만 직접 호출합니다. DisconnectController 또는
자식 없는 부모 Stop은 호출하지 않습니다. PCI 속성 쓰기, GPU MMIO, 리셋,
펌웨어/NVRAM 쓰기 또는 unlock은 요청하지 않지만 드라이버 내부 레거시 비디오
효과는 발생할 수 있습니다.

새 코드/바인딩/PCI/관계/PCD/입력 상태가 두 번 일치해야 하고 일회성 호출 전
의도를 flush합니다. 오류 후에도 이전 자식 프로토콜을 질의하거나 저장한 GOP/
mode 할당을 역참조하지 않습니다. 네 관계에서 자식 관계만 제거되어 세 관계가
되어야 합니다. 소유자와 포인터 두 관계, 공유 바이트0/개수1/1, command7,
속성718/지원1b77b와 전체 PCI 구성은 유지해야 합니다. 독립 PCD 검사는 유지합니다.
새 전체 핸들 탐색에 이전 자식이 없어야 하며 남아 있으면 보수적으로 차단합니다.
콜백 오류나 부분/예상하지 않은 상태는 인계를 차단합니다. 재시도/재연결 또는
자동 복원은 없습니다.

새 위험: 펌웨어 DisconnectController 래퍼를 거치지 않고 드라이버 Stop을 직접
호출합니다. 고정된 자식 경로는 레거시 INT10 비디오 서비스를 호출하며 유일한
GOP 자식을 제거/해제할 수 있습니다. PCI 소유자/BME가 남아 있어도 화면/입력 손실,
펌웨어 정지 또는 Windows 시작 실패가 가능합니다. 수동 전원 차단/USB 제거가
필요할 수 있으며 복구는 입증되지 않았습니다. 이전 소비자 전용 실험과 다른
경계이므로 USB 준비 전에 명시적 수락이 필요합니다.

전체 준비 시험은 직접 자식 수명주기193개, 실제 화면/PCD 수집33개를 포함해
통과했고 Python31개도 통과했습니다. 콜백 전/후 오류, 부분 변경, 남은 자식/관계,
소유자/포인터 손실, PCI/입력 변경, 기록 실패, 의도 기록 후 바인딩 변경, 잘못된
최종 키와 최종 입력 중 변경을 검사합니다. 해제된 자식 프로토콜 접근은 금지합니다.
네이티브 AMD64 EFI는46,592바이트이며 import/IAT/delay import 없음, NX/dynamic
base 활성입니다. SHA-256:
`bb82bd260c9b8df0142318692a090b8f28ecf8ecb8e3858593d2f145c8b20975`.
호스트 시험은 실제 복구를 입증하지 않습니다.

수락 및 USB 준비 확인 후에만: 작업을 저장하고 완전히 종료한 뒤10초 기다립니다.
ASUS Delete/F8 → UEFI USB DISK2.0으로 부팅합니다. Shift+G를 한 번 눌러 네 단계를
허용하고5초 기다린 뒤 최대1분 동안2초마다 Shift+V를 누릅니다. 두 번째 안내는
출력하지 않습니다. 키를 누른 채 유지하거나 부팅을 반복하지 마세요. 정지 또는
5분 후에도 Windows가 없으면 전원을 끄고 USB를 제거한 뒤 일반 Windows Boot
Manager를 선택합니다. 이는 복구 시도 경로이며 보장은 아닙니다.

성공해도 이번 실행의 자식 전용 제거를 입증할 뿐 부모 해제나 unlock은 아닙니다.
BME는 계속 활성 상태여야 합니다. 새 시험 전에 모든 캡처를 보관해야 합니다.
