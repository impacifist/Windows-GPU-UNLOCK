# 다섯 번째 AD104 부팅: 장치 전체 속성

[English](AD104-FIFTH-RESULT.en.md) | 한국어

2026-10-26 진단에서 두 읽기 전용 속성 질의가 모두 성공했습니다.

```text
current=0x0000000000000718 supported=0x000000000001b77b
```

현재 값 `0x718`은 I/O 디코딩(`0x100`), 메모리 디코딩(`0x200`), 버스
마스터링(`0x400`), VGA 메모리(`0x8`), VGA I/O(`0x10`)를 포함합니다.
PCI command는 `0007`로 유지되었습니다. BAR0 설명자의 별도 형식 검사도 다시
통과했습니다. BAR별 지원 플래그는 0이며 위 장치 전체 지원 속성과는 다른 값입니다.

IMG29의 정적 Stop 경로에서 관찰한 계산을 적용하면
`(0x1b77b & 0x700) | 0x18 = 0x718`입니다. 이 후보 Disable 마스크는 현재
보고된 모든 속성을 포함합니다. 드라이버가 해당 경로에 도달하고 동작이 성공한다면
나열된 다른 속성과 함께 메모리 디코딩과 BME를 모두 비활성화할 수 있습니다.
이는 정적 코드와 질의 결과에서 도출한 예측이며 관찰된 Stop 효과가 아닙니다.
분기 선택, 콜백 성공, 부분 실패 동작 및 Windows 복구는 아직 검증하지 않았습니다.

속성 변경, DisconnectController, GPU MMIO, ROM 버퍼 복사, 드라이버 해제 또는
언락은 수행하지 않았습니다. 로그에 `query-only=1`, `unlock-eligibility=0`을
명시합니다. 메타데이터 모드의 `capture-complete=0`과 최종 `EFI_NOT_READY`는
예상 결과입니다.

캡처 파일 33개를 별도의 비공개 호스트 보관 위치로 복사했고 USB/복사본 SHA-256이
일치했습니다. 진단 로그는 396,263바이트입니다. USB EFI SHA-256은 준비한 산출물
`2949d1f816b0b201c98320d0b762c931571cdf1749bee0c377f07a47292a91b7`과
일치합니다. USB 원본은 변경하지 않았습니다. 오프라인 해제 감사는 위치, BME 및
드라이버 지문의 불일치를 계속 보고합니다. 동일 질의를 반복할 필요는 없으며
이번 결과 확인 작업에서 새 EFI를 준비하지 않았습니다.

상태 변경 테스트 전에 이 캡처에 맞는 수명주기 및 디코딩 복원 계약을 정의해야
합니다. 예상 자식/부모 연결 종료, 허용할 디코딩 변경, 부분 중지 처리 및 검증
성공 후 Windows 부팅 방법이 필요합니다. BME를 직접 지우거나 다른 보드의
해제 코드를 재사용하지 마십시오. 이번 결과는 언락을 검증하지 않습니다.
