# 20차 참석 후보: 제한된 BAR PROM 앞부분

실행 결과: [20차](AD104-TWENTIETH-RESULT.ko.md). 아래는 원래 후보 계약입니다.


[English](AD104-TWENTIETH-BOOT.en.md) | 한국어

빌드·호스트 검사 완료, 실제 실행 전입니다. 새 MMIO 위험이 있어 USB 준비 전에 명시적
승인이 필요합니다. [19차](AD104-NINETEENTH-RESULT.ko.md)는 시간차 읽기 및 직접 Windows
복귀를 재현했지만 참조 SS1/VGA_BASE 차이를 해결하지 못했습니다. 실제 PROM 증거는
여전히 없습니다.

기존 다섯 중지, Enable(0x300), 시간차 레지스터 배치와 새 상태 검사 후 BAR0
0x300000–0x3001fc만 읽습니다:128DWORD/512바이트. 첫 DWORD는 AA55 서명을
가져야 하며 오류·메서드 변경 시 즉시 중지합니다. 일반 펌웨어 데이터에는FFFFFFFF/BADF가
포함될 수 있으므로 첫 서명과 전송 상태에만 관련 보호를 적용합니다. 읽기 시퀀스 안에서
할당·파일·콘솔 콜백을 호출하지 않습니다.

0x300000 서명 재확인 한 번과 기존 chip-ID 읽기 한 번을 추가합니다. 합계는 PROM
DWORD 접근129회와 chip 읽기1회입니다. 읽기 전후 및 로그 후 PCI/속성/소유권/이전 자식
전체 상태를 다시 확인합니다. 서명 재확인만으로 모든 헤더 바이트의 시간적 안정성을
증명하지는 않습니다.

PCIR 서명, vendor10de/device2782, 캡처512바이트 안의 최소24바이트 구조,
알려진1MiB 창 이하의 0이 아닌 이미지 길이, 헤더를 포함하는 이미지 범위를 요구합니다.
포인터/구조가 앞부분 밖에 있으면 불완전/거부로 처리하고 추가로 읽지 않습니다.
전체 이미지·체크섬·체인·전체 ROM 동일성·FWSEC 또는 unlock을 검증하지 않습니다.
완전하게 허용된 앞부분 DWORD만 비공개 로그에 기록하며 PROM.BIN은 만들지 않습니다.
기존 펌웨어 RAM ROM과 오프라인 비교해도 앞부분 동일성만 확인할 수 있으며 전체 실제
PROM 해시 검증을 대신하지 못합니다.

새 V 입력 후 기존 승인된 Disable(0x300), 부모 중지 직후 전체 상태 반복 검사,
STATUS.TXT 및 Windows 복귀를 수행합니다. 헤더/로그/상태 실패는 V/Disable/Windows
전에 정지하므로 수동 복구가 필요할 수 있습니다. 재시도·재연결·리셋·BME/VGA 활성화·
업로드·unlock·자동 rollback은 없습니다. 새 MMIO 읽기는 부작용이나 hang을 일으킬 수
있고 Windows/화면/입력이 실패할 수 있습니다. 이 후보의 복구는 미입증입니다.

헤더 RAM 검사62,991개는130개 각 전송 콜백 오류, 서명/PCIR/식별자/길이 오류,
sentinel 형태의 정상 데이터, 최대 합법 PCIR 경계, intent flush 상태 변경,
출력 쓰기 오류/상태 변경을 검사합니다. 기존 시간차/decode-off/witness/캡처 검사도
유지합니다. mock은 실제 증거가 아닙니다. Native AMD64 PE55,808바이트, import 없음,
SHA-256은 `627d156e1a0ccb1fe4832f17f968667e577ae4206f90bee1b177739e675d283d`입니다.
빌더는 PROM-header→시간차→decode-off→decode-read를 요구하고 manifest는512바이트를
기록합니다. 별도 위험 승인 후에만 USB에 준비합니다.

준비 후: 작업 저장, 완전 종료,10초 대기, UEFI USB 선택. Shift+G 한 번으로 전체
단계를 허용합니다.5초 후 Shift+V를2초마다 최대1분 누릅니다. 해제 후 새 화면 안내는
없습니다.5분 안에 Windows가 없으면 전원 종료, USB 제거, 정상 Windows Boot Manager
선택. 한 번만 실행하고 재시도 전에 모든 캡처를 보관합니다.
