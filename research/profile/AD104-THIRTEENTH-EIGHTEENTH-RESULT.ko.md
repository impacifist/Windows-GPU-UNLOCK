# AD104 13–18차 결과: PCI 해제, 레지스터 읽기와 Windows 복귀

[English](AD104-THIRTEENTH-EIGHTEENTH-RESULT.en.md) | 한국어

## 결과

2026-10-27 MSI RTX 4070 Ti(`10de:2782 / 1462:5132`, AD104)에서 다섯 드라이버
중지, I/O·메모리 디코딩 활성화(BME/VGA 비활성 유지), 동일한 두 레지스터 배치,
디코딩 비활성화, 사용자 확인에 따른 직접 Windows 복귀가 성공했습니다.
Windows의 NVIDIA 610.88 드라이버도 GPU를 정상 인식했습니다. 한 번의 성공한
캡처·복귀 절차이며 unlock 또는 복구 보장을 뜻하지 않습니다.

[정제된 증거](ad104-thirteenth-eighteenth-evidence.json)에 각 실행의 단계 상태,
레지스터, 파일 수 및 진단 로그 SHA-256을 기록했습니다. 원본 펌웨어, 핸들,
플랫폼 식별자와 비공개 빌드 설정은 공개하지 않습니다. 분석 전에 USB 원본과
호스트 사본의 해시를 비교했고, 다음 시험 준비 시 원본을 덮어쓰지 않습니다.

## 실제 실행 순서

| 실행 | 관찰 결과 | Windows 관찰 |
| --- | --- | --- |
| 13 | 네 단계 후 IMG29 부모 Stop 성공. 관계 3→2, 속성 0x718→0, PCI command 7→0. 반복 검사 통과 | 사용자 Windows 복귀 |
| 14 | Enable(0x300) 성공, 속성 0x300/command 3. 첫 배치 마지막 0x840100에서 0xbadf5620. 두 번째 배치를 건너뛰고 의도적으로 정지 | 수동 전원 종료 후 정상 부팅 |
| 15 | 0x840100 제외, 마지막에 chip ID 재확인. 22회 읽기 두 배치 일치, V 입력 및 최종 검사 통과 | 부팅 화면 진전 없음, 수동 복구 |
| 16 | 같은 캡처 후 root Close 성공 확인. 마지막 기록은 main-log Close와 StartImage 전 | 화면 진전 없음, 수동 복구 |
| 17 | 별도 STATUS.TXT로 root/main-log Close 모두 성공 확인. StartImage-next 기록, 반환 기록 없음 | 화면 진전 없음, 수동 복구 |
| 18 | 캡처 및 V 입력 후 Disable(0x300) 한 번 실행. 저장된 부모 중지 직후 상태와 전체 비교 일치. command 0/속성 0 | 사용자가 직접 Windows 복귀 확인 |

전체 관련 관계는 8→6→5→4→3→2입니다. 순서대로 텍스트 소비자, GOP 소비자,
EDID 소비자, 직접 자식 Stop, 직접 부모 Stop을 수행했습니다. 포인터 관계 두 개만
남고 공유 플래그는 0, 포인터 수는 1/1입니다. 부모 Stop은 I/O·메모리·BME·VGA를
끄며 Enable(0x300)은 I/O와 메모리만 켭니다. 이때 command는 3이며 BME/VGA는 꺼져 있습니다.

18차의 디코딩 비활성화 후 복귀는 이 컴퓨터에서 Windows 시작 전 관찰된 부모
중지 직후 상태로 되돌리는 복구 가설을 지지합니다. 한 번의 성공으로 일반적인
인과관계나 복구 보장을 증명하지는 않습니다. 앞선 읽기의 GPU 내부 효과를
되돌리는 절차도 아닙니다. STATUS 파일 핸들은 17·18차 모두 열려 있었으므로
그 존재만으로 결과 차이를 설명할 수 없습니다.

## 레지스터 증거와 허용 한계

18차 각 배치는 21개 고유 오프셋과 끝의 chip ID 재확인을 포함해 22회 읽었습니다.
시작과 끝 chip ID는 0x194000a1, 두 배치는 동일하며 모든 읽기 콜백은 성공했습니다.
배치 사이에 의도적인 대기 시간은 없었습니다. 0x840100은 재시도하지 않았고,
BADF·전체 1 값·콜백 오류·메서드 변경·PCI/속성/소유권/식별자 보호 조건을 유지했습니다.

| 관찰 | 18차 값 | 해석 한계 |
| --- | --- | --- |
| chip ID 0x0 | 0x194000a1 | 관찰된 AD104 식별자이며 쓰기 프로필은 아님 |
| GFW 0x118128 / 0x118234 / 0x110100 | 0x8b8f / 0x3ff / 0x10 | 해당 참조 필드만 일치 |
| WPR2 high 0x1fa828 | 0 | 이것만으로 전체 cold-entry를 증명하지 못함 |
| feature PLM 0x823804 | 0xffffff8f | 보호 상태 관찰이며 전환 증거 없음 |
| SS0 0x82381c | 0x24020000 | 관찰값을 일반적인 불변 기준으로 사용할 수 없음 |
| SS1 0x823820 | 5 | 참조 프로필의 요구값 1과 다름 |
| 사용 가능 framebuffer MiB 0x1183a4 | 0x2ffa | 12,282 MiB이며 제품 표기 용량과 구분 |
| VGA_BASE 0x625f04 | 0x10e09 | 참조 프로필의 요구값 1과 다름 |

비교 대상은 고정된 AD104 연구 참조의 [profile.c](https://github.com/JustAResearcher/gpu-unlock-ada/blob/4e7fefcc4923f9e083d5324dc75a7d2f906af77f/windows/ad104-msi/profile.c) Registers() 조건이며 저장소의
기본 RTX 3090 프로필이 아닙니다. PCI BAR 위치도 참조와 다릅니다. 상수를 복사하거나
보호 조건을 낮춰 이 차이를 허용해서는 안 됩니다. FWSEC 실행, 보호 메모리 트랜잭션,
펌웨어 업로드, 리셋, unlock 또는 unlock 후 작업 부하는 수행하지 않았습니다.
기존 150,016바이트 펌웨어 RAM ROM은 실제 1 MiB BAR PROM 캡처와 다르므로
그 해시를 누락된 PROM 검증 대신 사용할 수 없습니다.

## 실패 표시와 구현 교훈

깜박이는 커서만으로 V 대기, 의도적 정지, 일반 오류 반환, 펌웨어/부트 관리자 정체,
화면만의 실패를 구분할 수 없습니다. 14차는 V 대기 전 의도적 정지였고 15–18차는
V 입력을 받았습니다. 초기 로그는 main-log Close와 StartImage 경계를 구분하지 못했습니다.
STATUS.TXT는 분리 전에 생성하고 덮어쓰기·핸들 별칭을 거부하며 제한된 단계 기록을
별도로 flush합니다. ExitBootServices 알림은 RAM 플래그만 변경하며 콜백 안에서 파일
작업을 하지 않습니다. 알림 이후 반환 경로에서도 파일 접근을 하지 않습니다.
따라서 StartImage 반환 기록 부재가 hang을 증명하지 않으며, 알림만으로 Windows
부팅 성공을 주장할 수도 없습니다.

레지스터 배치 안에서는 RAM에만 저장하고 배치 후 로그를 씁니다. 각 읽기 사이에
텍스트를 기록하면 버퍼가 차면서 암묵적 파일 쓰기가 발생할 수 있어 실제 실행 전에
수정했습니다. 다음 배치 전 로그 작업 뒤 전체 상태를 새로 검사합니다. 디코딩 비활성화도
intent flush 후 재검사, 한 번의 변경, 콜백 오류 후에도 사후 수집, 전체 상태 두 번 일치,
flush 후 최종 재검사를 요구합니다. 해제된 GOP/자식 메모리는 조회하지 않습니다.
실패하면 재시도·리셋·재연결·자동 rollback 없이 정지합니다.

모니터는 Windows에서 5120×1440/144 Hz이지만 EFI GOP는 1024×768입니다.
전체 화면 확대 시 가로가 약 2.67배 늘어납니다. 줄을 짧게 해도 종횡비는 수정되지 않습니다.
추가 하드웨어 상태 변수를 만들지 않도록 펌웨어 화면 모드는 바꾸지 않았습니다.

## 검증과 다음 시험

18차 EFI는 53,760바이트 AMD64 PE이며 import가 없고 SHA-256은
`92860ce034a6f12aca9560e06656515eca4d72c3e0988a5aea7078d83b883a76`입니다.
실행 전에 디코딩 비활성화 RAM 검사 2,074개와 Python 시험 33개를 포함한 준비 검사를
통과했습니다. 호스트 검사와 실제 하드웨어 결과는 별도 증거입니다. 핸들 별칭 허용 문제와
빌더 출력 디렉터리 선택 문제도 실제 후보 실행 전에 수정했습니다.

다음 시험은 동일한 읽기 배치 사이에 명목상 1초 Stall을 추가하고 대기 뒤 전체 상태를
새로 검사합니다. 성공한 디코딩 비활성화 및 상태 로그 복귀 경로를 유지합니다.
시간차 안정성과 복귀 재현성을 검사하며 unlock 허용 시험은 아닙니다.
새 레지스터·PROM 읽기·GPU 쓰기는 추가하지 않습니다.
