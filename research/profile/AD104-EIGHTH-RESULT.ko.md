# 여덟 번째 AD104 부팅: false 조건과 콜백 위치 확인

[English](AD104-EIGHTH-RESULT.en.md) | 한국어

실제 읽기 전용 관측은 스냅샷 일관성 검사를 통과했다. native PCD 토큰 `0x4ac`
조회가 두 번 모두 성공했고 각각 1,152개의 토큰 열거 단계 후 false를 반환했다.
토큰 부재나 조회 실패의 기본값이 아닌 실제 false 관측이다. 관측 당시 조건부
GOP SetMode 분기를 건너뛰는 동작을 뒷받침한다. 토큰의 의미 있는 이름이나
나중의 Stop 시점 값까지 보장하지는 않는다.

ConOut과 StdErr는 IMG14 로드 이미지 안의 인터페이스를 공유한다. OutputString
콜백은 RVA `0x34fc`, 콘솔 SetMode는 `0x378c`이다. 캡처된 섹션 테이블의
오프라인 검사는 이 콜백들이 실행 가능한 `.text`에 있음을 확인했다.
IMG14/15/16은 같은 로드 이미지의 중복 덤프이며 독립적인 소유자 세 개가 아니다.
위치를 확인한 것이며 내부 상태 변경 후의 안전성을 입증하지 않는다. 향후 텍스트
해제 코드는 시도 후 이 출력 콜백에 의존하면 안 된다.

자식 GOP SetMode는 IMG29 RVA `0x1ea0`이며 역시 캡처된 실행 가능 `.text`에
포함된다. GOP는 다섯 모드 중 `2`, 해상도 1024×768, 픽셀 형식 `1`, stride 1024,
프레임버퍼 base `0xd0000000`, 크기 `0x300000`이다. 프레임버퍼 내용은 읽지 않았다.
콘솔은 네 텍스트 모드 중 `0`, 속성 `0x0f`, 커서 열 0/행 1 및 숨김 상태다.
세 번의 스냅샷에서 상태가 일치했다.

PCD GetBool은 크기 `0x2e40`인 단일 로드 이미지의 RVA `0x4f4`에 있다. 이
프로토콜 제공자는 이번 자료의 드라이버 바인딩 이미지 덤프에 포함되지 않았다.
펌웨어 파일 GUID는 `80cf7257-87ab-47f9-a3fe-d50b76d89541`이지만 현재 이미지
덤프로 코드 해시나 실행 섹션 확인을 도출할 수 없다. 조회 결과로 그 구현의
지문을 대신할 수는 없다.

33개 파일을 새 비공개 호스트 폴더에 복사했으며 각 USB/복사본의 SHA-256이
일치했다. 로그는 398,582바이트이고 SHA-256은
`8142dcfca55d2a9511c6f810d6036fd6414e4c3cc4eb43adf1d9946bd134a43c`이다.
USB EFI도 준비한 이미지와 일치한다.
`7f9cba828a34660723e389465ffd9a190ce8ead20dc08d11477c741d0d5946b1`.
[정리된 증거](ad104-eighth-boot-evidence.json)를 참고한다. 원시 캡처와 절대 콜백
주소는 비공개로 유지하며 USB 원본은 변경하지 않았다.

사용자 복귀 후 Windows `nvidia-smi`는 `00000000:0B:00.0`의 RTX 4070 Ti,
드라이버 `610.88`, VBIOS `95.04.31.00.f0`를 보고했다. 현재 드라이버 사용
가능성을 확인했지만 읽기 전용 로그는 최종 Windows 인계를 추적하지 않는다.
메타데이터의 `capture-complete=0` 및 `EFI_NOT_READY`는 예상된 결과다.
텍스트 해제, 화면 SetMode, PCD setter, GPU MMIO 또는 unlock은 실행하지 않았다.
일곱 번째의 성공한 EDID 해제와는 별도 실험이다.

다음 작업은 새 조건 값 확인과 화면 상태 사후 조건을 포함한 출력 독립적인
텍스트 수명 주기 계약이다. PCD 제공자의 지문이 없다는 제한도 명시해야 한다.
이 캡처로 텍스트 또는 PCI 소유자 해제를 허용하지 않는다. 다음 EFI는 준비하지
않았으며 같은 관측을 그대로 반복할 필요도 없다.
