# 30차 후보: 남은 BCR 관측 분리

[English](AD104-THIRTIETH-BOOT.en.md) | [한국어](AD104-THIRTIETH-BOOT.ko.md)

[실제29차](AD104-TWENTY-NINTH-RESULT.ko.md)는 정확히 승인된 CPUCTL 거부 복구를 통해 Windows 자동 복귀를 확인했다. 이 후보는29차를 재현 가능하게 보존하고 이미 승인된28차 주소 목록의 부분집합을 사용한다. 거부된 RISC-V CPUCTL0x111388을 완전히 제거하여 아직 읽지 못한 BCR_CTRL0x111668에 도달한다. DMACTL0x11010c도 제외한다. 복구 성공에서 새로운 하드웨어 권한을 추론하지 않는다.

기존 드라이버 중지5단계, I/O+메모리만 디코딩 활성화, 고정22개 레지스터2배치, 전체1MiB PROM 캡처/재읽기/해시와 CPU 소유 FWSEC 감사를 반복한다. 이후 다음 순서의13-DWORD 배치를2회 수행한다.

`0, 0x110100, 0x110040, 0x110044, 0x110008, 0x1100f4, 0x110108, 0x1103c0, 0x111668, 0x82381c, 0x823820, 0x625f04, 0`.

칩 양끝194000a1, 이전 Falcon CPUCTL/선택자/VGA 일치, 원래 읽기 함수 포인터와 로깅 전후 새 PCI/소유 관계/입력 검사를 유지한다. BCR 직전 ENGINE0을 요구한다. 배치 내부에는 파일/콘솔/할당 콜백이 없다. BCR은 원시 값, VALID, 구성 코어 필드를 관측할 뿐이다. 구성 선택은 VALID=1일 때만 유효하게 해석하며 현재 실행 코어나 펌웨어 진입 준비를 증명하지 않는다. BCR 변화만으로 하드웨어 허용 정책을 만들지 않는다.

29차의 CPUCTL 전용 복구 예외는 컴파일하지 않는다. 빌더와 헤더는 BCR 모드와 예외의 결합을 거부한다. BADF5620을 포함한 BCR 오류 패턴, 전부1, 전송 오류, 필수 상태/함수/로그 변화는 영구 중지를 유지한다. 거부된 레지스터를 재시도하지 않는다. 완전한 관측과 허용 검사를 통과해야 새 Shift+V, 기존 Disable(0x300)1회, 저장된 부모 중지 후 상태 검사와 Windows 진입으로 진행한다. Disable 이후 GPU MMIO는 없다.

추가 관측26회/총262346회 Mem.Read이며 완전한28차보다2회 적다. GPU 제어 쓰기, 리셋, 코어 전환, DMA 시작, BME/VGA 활성화, 펌웨어 업로드/실행, 잠금 해제, 재연결, 자동 롤백은 추가하지 않는다. 화면/입력이 사라지거나 펌웨어/Windows가 멈출 수 있고 수동 전원 끄기/USB 제거가 필요할 수 있다. 새로운 BCR 오류 후 복구는 입증되지 않았으며29차 예외를 의도적으로 적용하지 않는다.

호스트 검사는 정확한 순서/횟수와 두 거부 주소 제외,26개 전송 오류 위치, BCR 오류 패턴4개, VALID/구성 코어 변화, ENGINE 불일치와 기존 로그/함수/상태 검사를 포함한다. 명시적 부정 컴파일 검사가 BCR+REFUSAL을 거부한다. RAM 모의 시험/빌드 성공은 실제30차 성공 증거가 아니다.

네이티브 AMD64 EFI67,584바이트, imports/IAT/delay imports 없음. SHA256:
`d49aa002a509404d9bd8495005d8f022d977be5d315fabb0270b860ad9da349e`.

USB 식별/소스/해시 검사와29차 보존 후 작업을 저장하고 완전히 종료하여10초 기다린 뒤 UEFI USB를 선택한다. Shift+G를1회 누르고10초 기다린 뒤 최대3분간2초마다 Shift+V를 누른다. 드라이버 해제 후 영상 갱신이 중지되므로 깜박이는 커서는 진행 표시가 아니다.10분 안에 Windows가 시작되지 않으면 전원을 끄고 USB를 제거한 후 평소 Windows Boot Manager를 선택한다. 복구는 보장되지 않는다.1회만 실행하고 재시도 전에 캡처를 보존한다. 체크리스트15/26(58%)는 유지된다.
