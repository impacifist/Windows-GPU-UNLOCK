# MSI RTX 4070 Ti: 첫 실제 진단 캡처

[English](AD104-FIRST-BOOT.en.md) | 한국어

2026-10-26에 로컬 커밋 `33670b1`에서 빌드한 캡처 전용 EFI를 MSI AD104
시스템에서 실행했습니다. 부분 관찰 결과이며 언락이나 완전한 ROM/레지스터
캡처가 아닙니다.

## 보존한 증거

USB에는 `DIAG00.TXT`(394,904바이트)와 `IMG00.BIN`부터 `IMG31.BIN`까지의
파일(합계 1,090,496바이트)이 있었습니다. 총 33개 파일을 Git에서 제외된
비공개 호스트 보관 위치로 복사했으며 각 SHA-256이 USB 원본과 일치했습니다.
이미지 32개의 크기도 진단 기록과 일치했습니다. 원본 펌웨어 이미지와 전체
프로토콜 그래프는 공개하지 않습니다.

[비공개 정보를 제외한 증거 요약](ad104-first-boot-evidence.json)에 원본
펌웨어나 PC 경로 없이 관찰값과 무결성 검사를 기록했습니다. 기존
[4070 Ti 연구 기여 PR #26](https://github.com/impacifist/Windows-GPU-UNLOCK/pull/26)의 후속 작업입니다.

USB EFI의 SHA-256은 다음과 같습니다.
`ce222b6034453da0a53532a39d36afdc6f2741bd0ca482d45ec19aa5ba6880f4`

## 확인 결과

- `0000:0b:00.0`에서 대상 하나를 발견했습니다. 장치 `10de:2782`, 서브시스템
  `1462:5132`, 클래스/리비전 DWORD `030000a1`입니다.
- PCI command/status DWORD는 `00100007`이었습니다. command 레지스터 `0007`은
  메모리 디코딩과 버스 마스터링이 활성화된 상태입니다. BAR0는 `fb000000`입니다.
- `ProbeEnvelope`는 `(cfg[1] & 6) == 2`, 즉 메모리 디코딩 활성화 및 버스
  마스터링 비활성화를 요구합니다. 관찰값의 결과는 `6`이므로 이것만으로도 초기
  거부가 설명됩니다. command 검사에서 먼저 반환하므로 BAR 리소스 설명자는
  검증되지 않았습니다.
- 로그는 `incomplete reason=ad104-envelope`, `capture-complete=0`, 진단 상태
  `8000000000000006`(`EFI_NOT_READY`)을 기록합니다. `PROM.BIN`은 없습니다.
  AD104 캡처 경로는 GPU MMIO 읽기 전에 반환합니다.
- 펌웨어는 1024 x 768 프레임버퍼를 가진 GOP 하나를 노출했습니다. 오프라인
  분석용 드라이버 바인딩과 프로토콜 소유권 관찰도 있지만, 이것만으로 안전한
  해제 절차가 확인되는 것은 아닙니다.
- 드라이버 바인딩 33개 중 하나는 이미지 핸들이 null이며 이미지 덤프는
  32개입니다. 구현의 덤프 상한은 32가 아닌 100입니다. 이 파일들은 드라이버
  바인딩 이미지 스냅샷이며 모든 로드된 이미지나 전체 시스템 펌웨어의 덤프가
  아닙니다. 동일 이미지 핸들 때문에 중복 스냅샷이 생길 수도 있습니다.
  수집 범위는 소유권 분석으로 확인해야 합니다.
- 초기 인계 준비는 성공했고 로드된 이미지 그래프에 Windows Boot Manager가
  있습니다. 로그는 Windows 시작 호출 전 진단 결과에서 끝나므로, 사용자가
  어떤 부팅 경로로 Windows에 복귀했는지는 입증하지 않습니다.

## 다음 조사

오프라인 후속 분석 결과는 [소유권 분석](AD104-OWNERSHIP.ko.md) 및
[이미지 해시 증거](ad104-ownership-evidence.json)에 기록했습니다. PCI-to-GOP
소유자 이미지는 IMG29에 있으며 `BIOS[INT10] Video Driver`를 포함합니다.
네이티브 NVIDIA GOP ID나 안전한 해제 절차는 확인되지 않았습니다.

수집한 소유권 그래프와 이미지 바이트를 오프라인으로 분석하여 GPU GOP의
드라이버/컨트롤러 관계를 식별합니다. 버스 마스터 보호 조건을 유지합니다.
PCI command 비트를 지우거나 드라이버를 해제하거나 이 부분 캡처를 언락
프로필로 취급하지 않습니다. 활성 버스 마스터링을 허용하는 향후 캡처 모드는
별도로 검토된 관찰 전용 계약과 테스트가 필요합니다. 동일한 진단을 다시
부팅해도 이 거부가 해결될 것으로 예상하지 않습니다.
