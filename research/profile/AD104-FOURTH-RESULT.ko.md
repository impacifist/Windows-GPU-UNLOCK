# 네 번째 AD104 부팅: BAR0 설명자 일치

[English](AD104-FOURTH-RESULT.en.md) | 한국어

2026-10-26의 리소스 전용 테스트에서 `GetBarAttributes`가 성공했습니다.
설명자가 유효하며 기존 허용 조건의 설명자 형식과 일치했습니다.

| 필드 | 관찰값 |
| --- | --- |
| 리소스 유형 | 0 (메모리) |
| Granularity | 32비트 |
| 최소값 | `0xfb000000` |
| 최대값 | `0xfbffffff` |
| 길이 | `0x01000000` (16 MiB) |
| 변환 오프셋 | 0 |
| 지원 속성 | 0 |
| 설명자 유효성 / 허용 형식 일치 | 1 / 1 |

로그의 PCI command는 `0007`이며 메모리 디코딩과 BME가 활성화되어 있습니다.
따라서 설명자에 관한 불확실성은 해소되었지만 전체 심층 읽기 허용 조건은 아직
만족하지 않습니다. `envelope-shape=1`은 MMIO 수행 허용을 뜻하지 않습니다.
GPU MMIO, ROM 버퍼 복사, BME 변경, 드라이버 해제 또는 언락은 수행하지
않았으며 `unlock-eligibility=0`을 명시합니다. ROM 버퍼 메타데이터는 여전히
`0x24a00`바이트입니다. 관찰 전용 모드의 `capture-complete=0`과 최종
`EFI_NOT_READY`는 의도된 결과입니다.

파일 33개를 별도의 비공개 호스트 보관 위치로 복사하고 USB/복사본 SHA-256이
일치함을 확인했습니다. 진단 로그는 396,085바이트입니다. USB EFI 해시는 준비한
산출물 `cf3bd58ef496604d653fc4d21da6030f27eb326dea49b5131ca590026d80014d`와
일치합니다. USB 원본은 변경하지 않았습니다. 오프라인 소유권 분석은 PCI-to-GOP와
텍스트 콘솔 관계를 다시 확인하지만 해제 안전성을 입증하지는 않습니다. 로그는
최종 Windows 시작 호출 결과를 입증하지 않습니다.

같은 리소스 부팅을 반복할 필요는 없습니다. 기존 ROM과 소유권 증거를 사용하여
별도로 명시적으로 검토된 소유권/수명주기 실험을 평가해야 합니다. 설명자 결과만으로
BME 해제나 레거시 비디오 소유자 중지가 안전하다고 판단하지 않습니다. 이번 캡처
확인 작업에서는 다음 EFI를 준비하지 않았습니다.
