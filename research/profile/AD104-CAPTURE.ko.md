# MSI AD104 캡처 및 진단 전용 MBR Windows 인계

[English](AD104-CAPTURE.en.md) | 한국어

날짜: 2026-10-26. PCI ID `10de:2782`, 서브시스템 `1462:5132`,
클래스/리비전 `030000a1`, 칩 ID `194000a1`에 대한 **캡처 전용** 옵션을
추가합니다. 언락 프로필을 추가하거나 `proven.json`의 범위를 넓히지 않으며,
GA102 프로필 생성기가 AD104 캡처를 허용하도록 변경하지 않습니다.

## 준비 과정의 두 가지 제약

기존 범용 진단의 심층 읽기는 검토된 3090/3090 Ti ID와 버스 1로 제한되어
있었습니다. `-Ad104Msi`는 별도의 읽기 전용 캡처 구현을 선택합니다. 유효한
PCI 위치를 검색하고 위치가 유지되는지 확인합니다. 펌웨어 캡처 대신 Windows의
버스 번호를 사용하지 않습니다.

이 Windows 설치는 UEFI 부팅과 EFI 로더 경로를 보고하지만, 시스템 부팅
파티션은 GPT ESP가 아닌 MBR/NTFS입니다. `-WindowsMbr`는 변환, 마운트,
포맷 또는 수정 없이 현재 시스템 부팅 파티션을 식별합니다. 진단 빌드에서만
사용할 수 있습니다.

2026-10-26의 첫 실제 진단 부팅에서는 부분 캡처를 얻었으며, 버스 마스터링이
활성화되어 AD104 MMIO/PROM 읽기가 거부되었습니다.
[첫 부팅 결과](AD104-FIRST-BOOT.ko.md)와
[비공개 정보를 제외한 증거 요약](ad104-first-boot-evidence.json)을 참고하십시오.
이 로그는 Windows 자동 복귀나 완전한 GPU 캡처를 입증하지 않습니다.

## AD104 읽기 허용 조건

MMIO 전에 NVIDIA 디스플레이 컨트롤러가 정확히 하나인지, PCI/서브시스템/
리비전이 일치하는지, 메모리 디코딩은 활성화되고 버스 마스터링은 비활성화되어
있는지 확인합니다. BAR0는 32비트이며 16 MiB 경계에 정렬되고 크기가 16 MiB여야
하며 리소스 설명자와 일치해야 합니다. 디코딩이나 버스 마스터링을 활성화하지
않습니다. 장치 핸들, 인터페이스, BDF를 고정하고 메모리 할당 및 리소스 콜백 후
PCI 구성 256바이트 전체를 다시 확인합니다. 잘못된 세그먼트/버스/장치/기능
범위는 거부합니다.

첫 장치 읽기는 AD104 칩 ID와 일치해야 합니다. 나머지 고정 레지스터 목록은
별도로 공개된 AD104 진단의
[gpu-unlock-ada 커밋 4e7fefcc](https://github.com/JustAResearcher/gpu-unlock-ada/blob/4e7fefcc4923f9e083d5324dc75a7d2f906af77f/windows/ad104-msi/diagnostic/src/sample.c)를 따릅니다.
총 22개 레지스터 값과 제한된 1 MiB PROM 영역을 읽습니다. 레지스터 오류나
오류 표식 값이 나오면 중단합니다. 완료된 관찰 결과를 기록하려면 PROM 서명이
일치하고, 마지막 칩 읽기가 일치하며, 핸들/인터페이스/BDF/구성이 유지되어야
합니다. 불완전한 쓰기, 기존 덤프 또는 파일 I/O 오류가 있으면 캡처 완료로
인정하지 않습니다. 원본 캡처는 비공개로 보관합니다.

메타데이터나 완료된 캡처만으로 펌웨어 트랜잭션을 허용하지 않습니다. MMIO 읽기와
펌웨어 콜백은 검토된 실제 테스트가 필요합니다. 진단이라는 이름이 플랫폼별
부작용이 없음을 보장하지 않습니다.

## MBR 부팅 관리자 식별

빌드는 USB가 아닌 MBR 디스크에 현재 `IsSystem` 파티션이 하나 있어야 합니다.
디스크 서명은 0이 아니어야 하며, 활성 type-7 파티션과 512바이트 논리 섹터가
필요합니다. 파티션 번호, 시작 LBA, 크기 및 실제 시스템 부팅 볼륨의
`EFI/Microsoft/Boot/bootmgfw.efi` 크기와 SHA-256을 기록합니다. 시스템 부팅
파티션과 Windows OS 파티션을 구분합니다.

실행 시 파일시스템 장치 경로 하나만 해당 MBR 서명과 영역에 일치해야 합니다.
GPT 서명, USB/USB Class/USB WWID 상위 경로, 반복된 파티션 노드, 잘못된 경로,
영역 오버플로 및 모호한 일치는 거부합니다. 디스크 서명은 식별 정보이며 인증
수단은 아닙니다.

진단은 고정된 부팅 관리자 경로를 읽고 제한된 파일 메타데이터를 검증한 뒤
파일/루트를 닫습니다. SHA-256과 볼륨 경로를 다시 확인하고, 검증한 바로 그
바이트를 `LoadImage`에 전달합니다. 해시 확인 후 파일을 다시 열어 다른 내용을
로드하지 않습니다. 기존 GPT 선택이 기본값이며, MBR 진단 구성을 언락/해제
빌드에 사용할 수 없습니다. Windows 업데이트로 고정된 이미지가 바뀌면 다시
빌드해야 합니다.

USB 부팅 시 펌웨어가 Simple File System을 통해 부팅 볼륨을 실제로 노출해야
합니다. Windows에서 접근 가능하다는 사실만으로 이를 입증할 수 없습니다.
볼륨 누락이나 로드 실패는 실제 테스트에서 확인해야 할 제약입니다. 진단은
NTFS 드라이버를 설치하거나 자동 복구를 보장하지 않습니다. 관찰 전용 USB의
실패 경로는 펌웨어로 제어를 반환하지만 이후 부팅 동작은 해당 PC에서 검증해야
합니다.

## 로컬 준비

빌드만 수행합니다. 시스템 부팅 볼륨 접근에 필요한 경우 관리자 권한의 Windows
PowerShell을 사용하십시오.

```powershell
.\research\profile\build-probe.ps1 -Ad104Msi -WindowsMbr `
  -Clang 'C:\TOOLS\LLVM\bin\clang.exe' `
  -LldLink 'C:\TOOLS\LLVM\bin\lld-link.exe'
```

신뢰할 수 있는 설치된 도구 경로를 사용하십시오. 펌웨어 자산은 필요하지 않습니다.
출력은 `internal-boot/boot/build/probe-ad104-msi/BOOTX64.EFI`이며 인접한
매니페스트에 소스, 로컬 구성 및 바이너리 해시가 기록됩니다. 비공개 파티션/
이미지 고정값을 담는 `platform-config.h`는 Git에서 제외됩니다. 관련 없는 기존
내부 구성은 덮어쓰지 않고 거부합니다.

스크립트는 USB 복사, 부팅 변수 수정, 언락 준비, 드라이버 해제, GPU 상태 변경
또는 재부팅을 수행하지 않습니다. 사용자가 현장에 있는 실제 캡처를 별도로
승인하기 전에 산출물과 복구 절차를 검토하십시오. 미디어 준비 시 기존 부팅
파일을 보존하십시오.

호스트 전용 검사:

```powershell
.\research\profile\test-capture-preparation.ps1 -VcVars 'C:\Path\to\vcvars64.bat'
.\internal-boot\boot\test-diagnostic.ps1 -VcVars 'C:\Path\to\vcvars64.bat'
```

## 로컬 검증 기록

- RAM 전용 AD104 검사 148개: 정확한 허용 조건, 다중 대상, BDF 범위와 변동,
  리소스 실패, 각 레지스터 오류/표식, 부분 PROM, PROM 서명 변경, 최종 ID 변경,
  덤프 실패를 검사했습니다.
- 합성 MBR 볼륨/이미지 검사 66개: ID/영역 불일치, USB 변형, 잘못되거나 반복된
  노드, 모호성, 해시/길이/메타데이터 오류, 닫기/할당 실패 및 모의 `LoadImage`에
  전달된 정확한 버퍼를 검사했습니다.
- 기본 GPT 일치 회귀 검사 4개를 통과했습니다.
- 호환되지 않거나 진단 전용이 아닌 컴파일 조합 16개가 거부되었습니다.
- 기존 진단, 고정 프로필 4개, 검증된 GA106 및 범용 프로브 호스트 테스트는
  마지막 AD104/MBR 개별 수정 전에 통과했습니다. 해당 수정은 기존 프로브
  분기를 변경하지 않습니다.
- clang/lld 21.1.6으로 네이티브 AMD64 EFI를 빌드하고 PE 검증을 통과했습니다
  (imports/IAT/delay imports 없음). 로컬 매니페스트의 하드웨어 테스트 표시는
  false입니다. 생성된 EFI나 독점 부팅 이미지는 커밋하지 않습니다.

매니페스트는 빌드 시점의 산출물을 설명하며 실시간 테스트 기록이 아닙니다.
이후 별도로 승인된 여분의 USB에 산출물을 복사하고 사용자가 부팅했습니다.
실제 결과는 호스트 검사와 구분하여 첫 부팅 보고서에 기록했습니다. 언락은
시도하지 않았으며 캡처 허용 조건도 그대로 유지합니다.
