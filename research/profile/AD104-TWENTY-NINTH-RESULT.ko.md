# 29차 결과: 정확한 거부 관측 후 복구

[English](AD104-TWENTY-NINTH-RESULT.en.md) | [한국어](AD104-TWENTY-NINTH-RESULT.ko.md)

2026-10-27 실제29차 시험 후 Windows가 자동 시작되었음을 사용자가 확인했다. 첫 선택 배치는9회 호출 후 중단되었다. RISC-V CPUCTL0x111388은 전송 상태0과0xBADF5620을 반환했다. 관측은 여전히 실패/미완료(EFI_NOT_READY)이며 이 값을 CPU 상태로 인정하지 않는다.

별도로 승인된 복구 경로에서 두7-DWORD 필수 상태 배치가 통과했다. 각 배치는 chip194000a1, Falcon CPUCTL10, ENGINE0, SS0=24020000, SS1=5, VGA=10e09, chip194000a1이었다. 복구 허용 검사와 새 입력/최종 상태 검사가 통과했다. Disable(0x300)1회가 성공했고 두 사후 검사는 command0/attributes0/소유 관계2를 기록했다. Windows 허용과 시험 결과도 성공했다. STATUS에는 실패한 관측, 성공한 재검사/디코딩 해제, 루트/로그 닫기, StartImage-next0이 독립적으로 기록되었다. 이 마지막 표시만으로 OS 시작을 증명할 수 없지만 사용자가 자동 복귀를 확인했다.

BCR_CTRL과 두 번째 선택 배치는 읽지 않았다. 선택9회와 복구14회로 총262343회 Mem.Read였다. 디코딩 해제 후 MMIO, 리셋, 코어 전환, 펌웨어 업로드/실행, 잠금 해제는 없었다. 이번 결과는 정확히 이 거부에 대한 복구1회 성공이며 일반 복구 안전성이나 레지스터 접근성, 펌웨어 실행 준비를 입증하지 않는다.

원본36개 파일을 비공개로 복사하고 원본/사본 해시를 검증했다. DIAG433738바이트 SHA256 d0384b5c23515b9937afc7c5614a796796a98b34aad822ddc5e796bdc14ab0af; STATUS471바이트 SHA25643bc9bc4eed244c4c14624a71f7b1832fc07ca2b2c787e641b34b27b9a92e413. PROM 해시는 accf2a054de0ec394078f933f74356ed7c4057ee0bd1ce6734cacda54ca9e1e1로 동일하다. 실행 EFI는 f6de8e330777bd344c229ac37ec8844ac3f66b77f487d7dd09e3d3ee079c41c0이다.

다음 시험은 승인된28차 읽기의 부분집합으로 BCR_CTRL을 분리하고 거부된111388은 제외한다.29차는 재현 가능하게 보존하고 BCR 후보에 복구 예외를 적용하지 않는다. 체크리스트15/26(58%)는 유지된다. 복구 증거만으로 펌웨어 진입 자격이 완성되지는 않는다.
