# 여섯 번째 테스트: 해제 없는 실제 토폴로지 사전 관찰

[English](AD104-SIXTH-BOOT.en.md) | 한국어

새로 구현한 캡처별 검색 코드를 실제 펌웨어에서 실행합니다. 저장 주소를 재사용하거나
속성 질의만 반복하지 않습니다. 로드된 코드 해시, 크기, 코드 유형, 버전 및 Stop
RVA로 네 드라이버 바인딩과 IMG29 안에 Stop이 있는 null 이미지 바인딩을 찾습니다.
IMG08은 runtime-services 코드로, 나머지는 boot-services 코드로 고정합니다.
다섯 캡처에서 코드 해시가 동일하고 해시한 text 범위에는 재배치 항목이 없습니다.

예상 활성 관계 여덟 개를 확인합니다. GPU/디스플레이 자식/콘솔의 추가 활성 열기나
관련 에이전트가 다른 핸들에 가진 추가 활성 열기는 거부합니다. 핸들 1,024개,
핸들당 프로토콜 256개, 프로토콜당 열기 항목 512개로 제한하고 수동적 관찰은
제외합니다. 두 번째 새 수집에서도 입력 핸들/콜백 포인터 및 IMG08 공유 바이트/
카운터(`1`, `1`, `1`)가 같아야 합니다. 이 값은 아직 의미를 확정하지 않은
로드 상태 관찰이며 전체 동작 의미가 입증된 것은 아닙니다.

예상 기록은 `ad104-runtime-preflight topology-status=0x0000000000000000`입니다.
`roles=0xf`, null 바인딩 존재 및 일치 관계 여덟 개로 검색 결과를 설명합니다.
거부 단계 1은 드라이버 검색, 단계 2는 그래프 검사입니다. 단계 0도 전체 허용을
뜻하지 않습니다. 실패는 유용한 증거이며 지문을 완화하거나 반복 부팅할 근거가
아닙니다.

**성공은 토폴로지/지문의 일관성만 의미합니다.** 리소스 허용은 별도 보고합니다.
실제 키보드 입력 동작, 원자적 스냅샷, GPU 콜드 상태, 안전한 Stop 또는 해제/언락
허용을 입증하지 않습니다. `release-authority=0`, `cold-state-known=0`,
`input-execution-tested=0`을 유지합니다. 메타데이터 경로의 `capture-complete=0`과
`EFI_NOT_READY`도 유지합니다. Stop, DisconnectController, 속성 쓰기, GPU MMIO,
ROM 복사, 펌웨어 실행 또는 언락을 포함하지 않습니다. 기존 이미지 덤퍼와 같이
로드 이미지 포인터/할당은 펌웨어 프로토콜 계약을 신뢰합니다.

빌드 옵션은 `-Ad104Msi -Ad104Metadata -Ad104Resources -Ad104Preflight -WindowsMbr`입니다.
구현 `8c22c7e`의 산출물은 28,672바이트이며 SHA-256은
`df8245799c9c4ca010e56e71d7a21c486ac6933862eed6fd271b68bba0d7a169`입니다.
네이티브 AMD64 PE 검사 통과(imports/IAT/delay imports 없음, NX/dynamic base).
호스트 검사 통과: 새 검색/그래프 18개, 심층 AD104 151개, 메타데이터 24개,
ROM 버퍼 113개, 리소스 66개, MBR 66개, GPT 4개, 거부된 빌드 조합 21개,
Python 31개입니다. 새 C 검사는 RAM 펌웨어 모의 객체와 테스트 해시를 사용합니다.
네이티브 빌드 검사와 실제 실행 증거는 구분합니다.

준비 전에 이전 캡처와 EFI를 보관합니다. 작업을 저장하고 캡처 USB를 연결한 채
`shutdown /s /t 0`을 실행합니다. 완전히 꺼진 뒤 10초 기다리고 ASUS Delete →
F8 → 8GB USB DISK 2.0의 UEFI 항목을 선택합니다. 테스트 키는 필요하지 않습니다.
4분 안에 Windows로 복귀하지 않으면 전원을 끄고 USB를 제거한 뒤 일반 Windows
Boot Manager로 부팅합니다. 자동 복귀는 보장하지 않습니다. 다시 부팅하기 전에
새 캡처를 보존합니다. BIOS 설정 변경은 필요하지 않습니다.
