# 스물아홉 번째 후보: 거부된 관측 후 제한된 Windows 복구

[English](AD104-TWENTY-NINTH-BOOT.en.md) | [한국어](AD104-TWENTY-NINTH-BOOT.ko.md)

검토용 빌드 완료, 사용자가 새 실패 후 복구 위험과 스테이징을 명시적으로 승인했습니다. 실제29실행 전이며 검증된 스테이징 전에28원본을 보존합니다. 선택적 읽기 실패 한 경우의 처리를 바꾸지만 실패한 값을 정상으로 허용하거나 실행 권한을 부여하지 않습니다. USB/소스/보존 파일/해시 검증 후 검토된 바이너리만 스테이징합니다.

## 오프라인 발견

[NVIDIA gpu_access.c](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/src/nvidia/src/kernel/gpu/gpu_access.c)는 반환 데이터의 PRI오류 마스크/코드를 검사해 sanity-check 처리기로 보냅니다. 성공한 호스트/PCI 전송과 유효한 장치 데이터는 구분해야 합니다. 검색한 공개 소스로0xBADF5620의 정확한 원인/권한 수준/무해함은 입증하지 못했습니다.25/28은 읽기가 반환된 뒤 소프트웨어 보호 정지를 기록했으며 MMIO호출 자체의 정지 증거가 아닙니다. 권한 변경/오류 지우기/거부 레지스터 재시도는 없습니다.

## 정확한 새 분기

28을 반복하고 원래 FalconObserve는 센티널에서 여전히 EFI_NOT_READY를 반환합니다. 첫 선택 배치의9번째만 대상입니다: 오프셋0x111388, 콜백상태0, 정확히0xbadf5620,9개상태모두0,칩194000a1,FalconCPUCTL0x10 및 이전샘플 일치,ENGINE0. 이전 값은 기존 검사를 통과해야 하며 부분 결과 로그 후 원래 Mem.Read 포인터와 전체PCI/소유권/입력 상태를 재검증합니다. 다른주소/값, 모두1, 전송/메서드 오류 또는 두번째 배치 실패는 기존 영구 정지입니다.

원래 관측 실패를 DIAG/STATUS에 기록하고 나머지 선택 읽기를 중단합니다(BCR_CTRL/두번째 선택 배치 없음). 별도의1회 복구 진입은 의도를 플러시하고 새 상태를 확인한 뒤 필수 상태7회씩 두 배치를 읽습니다:
`0, 0x110100, 0x1103c0, 0x82381c, 0x823820, 0x625f04, 0`.
칩 시작/종료194000a1,CPU/선택자/VGA는 이전값,ENGINE0을 요구합니다. 각 읽기 전후 원래 포인터와 로그 전후 전체 상태를 검사하고 읽기 중 할당/파일/콘솔 콜백은 없습니다. 추가 오류/불일치는 디코딩 해제/Windows 없이 정지합니다.

14회 재검사와 별도의 복구 진입 기록 후 새 Shift+V/최종 상태 검사를 요구합니다. 이후 기존1회 Attributes Disable(0x300)와 정확한 부모 중지 후 상태를 검증하고 STATUS기록 뒤 PCI/소유권을 재검증합니다. Disable 뒤 GPU MMIO는 없습니다. Windows 복구 진입이 성공해도 관측은 미완료/NOT_READY이며 코어 상태 샘플링 성공이 아닙니다. STATUS는 거부/재검사/디코딩 해제 및 Windows 표식을 별도로 보존합니다. 쓰기·플러시/레코드 한도/ExitBootServices 검사는 유지합니다.

새주소/리셋/코어전환/시작중지/DMA시작/BMEVGA활성화/펌웨어업로드·실행/언락/재연결/자동롤백은 없습니다. 그러나 거부된 읽기 뒤 계속하는 것은 새 위험 경계입니다. 검사로 모든 하드웨어 부작용을 감지할 수 없으며 화면/입력/Windows실패·정지, 수동 전원차단/USB제거가 필요할 수 있고 복구는 미검증입니다. 기존 성공 경로 승인으로 이 분기를 승인한 것은 아니므로 이 분기의 별도 명시적 승인을 받았습니다.

정상 관측은 추가28회/전체262348회, 정확한 거부 분기는 선택9+필수14=추가23회/전체262343회이며 거부 주소 재시도는 없습니다. 매니페스트 CanRecoverKnownObservationRefusal=true,RecoveryRegisterReads14,RefusalPathAdditionalReads23이며 DMACTL/리셋/펌웨어실행/언락=false입니다.

호스트는 정확한 거부/부적합상태,14개 복구 전송 오류, 필수 상태/메서드/로그/소유권/증거 파일 오류, 새V와Disable전후 검사를 확인합니다. 검토에서 로그 중 읽기 포인터 교체 문제를 발견해 원래 포인터를 전달하도록 고쳤고, 호출 가능한 대체 함수로 바꿔도 복구MMIO/Disable이0임을 검증합니다. 실제 증거 파일 래퍼의 NOT_READY 보존/쓰기·플러시 오류/한도/ExitBootServices 후 쓰기 금지도 검사합니다. RAM모의 검사이며 실제 복구 증거가 아닙니다.

AMD64/가져오기 없음 EFI69,632바이트 SHA256:
`f6de8e330777bd344c229ac37ec8844ac3f66b77f487d7dd09e3d3ee079c41c0`.
체크리스트15/26(58%)유지, 언락/실제 펌웨어실행은 미입증입니다.

검증된 스테이징 후 작업저장/완전종료/10초/UEFIUSB/Shift+G한번,10초후Shift+V를2초마다최대3분.10분후Windows가없으면전원차단/USB제거/정상BootManager.한번만실행하고캡처보존.복구 보호 정지도 키로 재개할 수 없습니다.
