# 스물세 번째 후보: RAM 전용 FWSEC 준비 리허설

[English](AD104-TWENTY-THIRD-BOOT.en.md) | [한국어](AD104-TWENTY-THIRD-BOOT.ko.md)

스테이징 전 빌드 및 호스트 테스트를 수행하며 실제 실행 결과는 아직 없습니다.

테스트22와 동일한 5단계 중지, Enable(0x300), 레지스터 44회, PROM 262,274회 및 칩 2회 읽기를 반복합니다. GPU 주소/쓰기, 리셋, 퓨즈 읽기, 펌웨어 업로드/실행을 추가하지 않습니다. 디코딩 해제와 Windows 복귀 절차는 동일합니다.

정확한 PROM/파서/구조/페이로드 감사 후 FWSEC 이미지 66,304바이트만 기존 두 번째 1MiB 읽기 검증 버퍼로 복사합니다. 버퍼의 분리와 범위를 확인하고 이미지 앞뒤에 16바이트 카나리를 둡니다. 운영 FRTS 패치 함수를 가상 오프셋 0x100000000으로 호출합니다. 이 값은 인코딩 테스트 벡터이며 실제 장치 주소로 할당하거나 승인하지 않습니다.

모든 이미지 바이트를 원본 및 예상 명령과 독립적으로 비교합니다. 허용 쓰기 위치는 이미지 오프셋 0x10240의 44바이트와 0x1000c(DMAP+44)의 4바이트뿐입니다. 변경 바이트 수와 패치 이미지 해시를 기록하고 카나리 및 원본 PROM 해시를 다시 확인합니다. 패치된 바이트는 정상 파일 읽기 검증으로 덮어쓰며 실행 자산으로 저장하거나 업로드/실행하지 않습니다.

가상 퓨즈 값 0..15에 대한 서명 선택도 결합합니다. versions=3, 서명 크기384에서 가상 값0/1은 오프셋0/384이며 2..15는 출력 변경 없이 거부해야 합니다. 실제 퓨즈 값이나 서명 인증, 실행 권한을 입증하지 않습니다. 호스트 테스트는 잘못된 퓨즈/버전/크기/NULL/오버플로 및 패치 정렬/범위 오류도 확인합니다.

패치/서명 감사 불일치만으로는 기존 PROM 보존/복구를 막지 않습니다. 원본 변경, 카나리 손상, 로그 또는 하드웨어 상태 오류는 복귀를 차단합니다. 트랜잭션 컨텍스트나 프로필 검증, 선택자 래치를 설정하지 않습니다. 패치/서명 함수는 RAM 전용으로 연결하며 장치 트랜잭션 함수는 제외합니다.

실제 캡처의 호스트 테스트만으로 바이트 변환을 검증할 수 있습니다. 다음 EFI는 캡처/복구와의 통합을 확인하며 SS1/VGA/BAR/기준 ROM 차이나 실행 준비 문제를 해결하지 않습니다. 진행률은15/26(58%)입니다.

작업 저장 후 완전히 종료하고10초 기다려 UEFI USB로 부팅합니다. Shift+G 한 번,10초 후 Shift+V를2초마다 최대3분 누릅니다.10분 후에도 Windows가 시작하지 않으면 전원을 끄고 USB를 제거한 뒤 정상 Windows Boot Manager를 선택합니다. 이번 실행의 복구는 보장되지 않습니다. 한 번만 실행하고 캡처를 보존합니다.

Native EFI: 64,000 bytes, AMD64, no imports. SHA-256:
`1b0ab6ba12c8d270693d1faa4b6c0d013b9a82572c21baa93a59ff13cd53f508`.

실제 PROM 호스트 리허설: 57개 검사 통과, 변경 9바이트. 패치 RAM 해시
`0bca65c5d5f41cec855acd8009340a86a1e08d117cb9c1a716cb444f3d0a2d52`.
네이티브 빌드에는 테스트 오류 주입 및 장치 트랜잭션 함수가 없습니다.
