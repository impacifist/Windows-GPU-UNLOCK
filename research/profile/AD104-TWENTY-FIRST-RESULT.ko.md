# 21차 결과: 전체 PROM 캡처, FWSEC 위치 확인, Windows 복귀

[English](AD104-TWENTY-FIRST-RESULT.en.md) | 한국어

2026-10-27 승인된 결합 시험에서 고정1MiB BAR PROM 창을 캡처하고 같은 부팅의
512바이트 앞부분 일치, GPU/상태/재확인, 파일 재읽기/EOF/해시/Close/Free/최종
허용 검사를 통과한 뒤 decode-off를 수행했습니다. 사용자는 Windows 자동 복귀를
확인했습니다.36개 파일은 비공개 복사 및 SHA-256 검증했고 실제1,048,576바이트 PROM은
EFI 로그 해시와 같습니다:
`accf2a054de0ec394078f933f74356ed7c4057ee0bd1ce6734cacda54ca9e1e1`.
이전150,016바이트 펌웨어 RAM ROM 전체가 물리 PROM 앞부분과 정확히 일치합니다.
[정제된 증거](ad104-twentyfirst-boot-evidence.json)는 해시/메타데이터만 담고
원본 펌웨어·플랫폼 식별자·로드 코드는 공개하지 않습니다.

## 확장 체인과 새 자료

생산 파서와 범위를 제한한 오프라인 검사는 네 이미지를 식별합니다:

| 오프셋 | 바이트 | 데이터/코드 종류 | 유효 마지막 |
| --- | --- | --- | --- |
| 0 | 64,512 | PCIR/legacy0 | 아니오 |
| 64,512 | 85,504 | PCIR/EFI3 | 아니오 |
| 150,016 | 24,576 | NPDS/0xe0 | 아니오 |
| 174,592 | 451,584 | NPDS/0xe0 | 예 |

두 번째 이미지의 일반 PCIR final 비트는 설정되어 이전 두 이미지 RAM 보고서와
일치합니다. 그러나 NVIDIA NPDE revision0x100/길이16은 생산 파서에서 유효 마지막을
false로 바꿔 추가 이미지를 가리킵니다. 이는 이전 제한된 해석의 보완이며 동일한 RAM
앞부분이 물리 ROM 전체는 아니었습니다. 이 탐색만으로 모든 확장 이미지 체크섬/유효성을
주장하지 않습니다.

FWSEC-FRTS는 RAM ROM 밖인0x45480(283,776)에서 시작합니다. 호스트 생산 파서는0을
반환했고 출력 범위를 별도로 캡처 안에서 확인했습니다.

| 항목 | 관찰 |
| --- | --- |
| 이미지 오프셋/길이 | 0x45480 / 0x10300 (66,304) |
| IMEM PA/길이/VA | 0 / 0xf500 / 0 |
| DMEM PA/데이터 오프셋/길이 | 0 / 0xf500 / 0xd80 |
| PKC/interface 오프셋 | 0xb24 / 0x1c |
| microcode/engine | 9 / 0x400 |
| 서명 수/버전 | 2 / 3 |
| 서명 영역 오프셋/길이 | 0x45180 / 768 |

이미지 SHA-256:
`e604f9be77c4f45d14ccdd2e45caef480801342ec7833e8618c70bbf34c60ab9`.
서명 영역 바이트 SHA-256:
`df4953bd74c6c97736ba433a78db9cb27487c78e332445604379dabe7027a4f2`.
서명 영역 해시는 바이트 식별이며 서명 인증이 아닙니다.

## 참조 차이와 남은 조건

고정 AD104 참조는 다른 PROM 해시(c81eb48f…3ad3fb4), 이미지0x45488 및 서명0x45188을
요구해 두 오프셋이8바이트 늦습니다. 나머지14개 descriptor 필드는 위 구조와 같습니다.
참조 payload/서명 원본은 로컬 체크아웃에 없으므로 구조 유사성으로 내용 동일성을
추정하지 않습니다. SS1=5/VGA_BASE=0x10e09도 참조1/1과 다르고 PCI BAR도 다릅니다.
참조 보호 조건을 낮추거나 프로필을 이식하지 않습니다.

위치/파싱/범위/해시 확인은 펌웨어 증거의 진전이며 인증·cold-entry·실행 권한은 아닙니다.
FWSEC나 캡처된 펌웨어를 실행하지 않았고 unlock 트랜잭션도 없습니다. 다음 관찰 전용
EFI는 같은 GPU 작업을 반복하고 생산 RAM 파서로 알려진 바이트를 검사합니다.
호스트 양성 시험은 이미 이 캡처를 파싱했으며 다음 부팅의 목적은 EFI 통합/재현성이지
descriptor 발견이나 실행 가능성 입증이 아닙니다.
