# AD104: 공유 소비자와 언락 입증 기준

[English](AD104-UNLOCK-EVIDENCE.en.md) | 한국어

## 최신 실제 결과

[30차](AD104-THIRTIETH-RESULT.ko.md)는 BCR의 BADF5620 반환 후 의도적으로 중지했다. Windows 진입은 시도하지 않았고 사용자의 복구 상세 기억은 불확실하다. 별도 [29차](AD104-TWENTY-NINTH-RESULT.ko.md)는 정확한 CPUCTL 거부 후 제한 복구와 Windows 자동 복귀를 입증했다. [31차](AD104-THIRTY-FIRST-BOOT.ko.md)는 거부된 세 레지스터를 제외하고 실제 측정된 배치 입력을 CPU RAM에서만 감사한다. PROM/FWSEC 파싱, 패치, 서명 조립은 인증/실행 허용이 아니다. [로드맵](ROADMAP.ko.md)15/26(58%)는 유지하며 SS1/VGA/참조 ROM, 자산/진입 검증은 남아 있다.

## 단순화된 테스트 자료 대신 실제 그래프

다섯 번째 캡처에는 수동적 관찰을 제외한 열기 기록 140개가 있습니다.
[비공개 정보를 제외한 소비자 보고서](ad104-active-consumers-evidence.json)는
다음을 식별합니다.

| 이미지 | GPU 관련 활성 역할 | 관찰된 다른 활성 역할 |
| --- | --- | --- |
| IMG29 | PCI 소유자 및 디스플레이 자식 관계 | 이 스냅샷에서는 없음 |
| IMG14 | Simple Text Output 소유자 및 콘솔 자식 관계 | 이 스냅샷에서는 없음 |
| IMG17 | GOP 소비자 | 이 스냅샷에서는 없음 |
| IMG08 | EDID Discovered 소비자 | 콘솔의 Simple Pointer 및 Absolute Pointer |

분석기는 이제 자식이 GOP를 노출하고 PCI 소유자와 같은 에이전트를 사용하도록
요구합니다. 수동적 열기는 제외하고 null ControllerHandle을 가진 애플리케이션의
exclusive 열기는 드라이버 관계와 구분하여 처리합니다. 열린 프로토콜이 있는
핸들 수와 각 관계의 ControllerHandle을 혼동하지 않습니다. 오프라인 연결
분석이며 완전한 런타임 해제 사전 검사가 아닙니다.

IMG08은 열린 프로토콜 핸들 두 개에 걸쳐 활성 관계 세 개를 가집니다.
디스플레이와 포인터 역할이 같은 드라이버를 공유하므로 네 역할의 합성 수명주기
자료는 OEM 해제 프로필로 부족합니다. 그래프만으로 EDID 역할 해제가 포인터
입력을 없앤다고 입증할 수는 없습니다.

## Stop 분석과 로드 이미지 구조

IMG08 Stop RVA는 `0x1464`입니다. 정적 분석에서 EDID 질의 성공 분기는 이미지
RVA `0x546a`의 바이트를 지우고 EDID 열기를 닫은 뒤 반환합니다. 다른 포인터
정리 경로는 리스트/카운터 갱신과 조건부 정리를 포함합니다. 이는 캡처된 코드가
컨트롤러에 따라 분기함을 보여주지만 공유 플래그의 전체 의미와 효과는 아직
알 수 없습니다. 콜백을 실행하지 않았습니다.

덤프는 메모리에 로드된 스냅샷입니다. IMG08의 `.text` RVA는 `0x1000`이지만
원래 파일 raw pointer는 `0x400`입니다. 이를 파일 구조용 디스어셈블러에 그대로
넣으면 잘못된 바이트를 해석합니다. `normalize-loaded-pe.py`는 섹션 raw pointer가
수집된 RVA 바이트를 가리키는 별도의 비공개 분석 복사본을 만듭니다. 범위를
검사하고 중복/잘린 섹션과 기존 출력 파일을 거부하며 원본을 보존합니다.
원래 공급업체 파일을 복원하는 것이 아니며 실행하지 않습니다. IMG29의 `.text`
raw pointer는 RVA(`0x2a0`)와 이미 같으므로 기존 IMG29 Stop 분석에는 영향이 없습니다.

비공개 경로로 오프라인 재현합니다.

```powershell
python research/profile/map-active-consumers.py C:\private\DIAG00.TXT --output C:\private\consumers.json
python research/profile/normalize-loaded-pe.py C:\private\IMG08.BIN --output C:\private\IMG08-analysis.bin
python -m unittest discover -s research/profile -p 'test_*.py'
```

Python 테스트 31개가 통과했습니다. 이번 작업에서 새 펌웨어를 빌드하거나 USB에
준비하지 않았습니다.

## 언락 증거로 인정하려면

1. 새 런타임 사전 검사가 이 컨트롤러, 관련 그래프 관계 전체, 정확한 콜백/코드
   지문 및 공유 소비자를 식별해야 합니다. 과거 스냅샷이나 보드 ID만으로 해제를
   허용할 수 없습니다.
2. 별도 수명주기 실험에서 콜백 결과, 그래프 변화, 키보드 상태, 제한된 디코딩
   활성화 및 부분 실패 처리를 검증해야 합니다. 예측된 BME 변경은 실제 GPU
   콜드 상태 관찰이 아닙니다.
3. 해제 후 필요한 보호 메모리 상태를 포함한 하드웨어 콜드 진입 검사를 통과해야
   합니다. 아직 해당 레지스터 증거를 수집하지 않았습니다.
4. PC별 트랜잭션에서 의도된 상태 변경과 독립적인 재확인 및 제한된 실패 처리가
   필요합니다. 트랜잭션은 실행하지 않았습니다.
5. Windows/드라이버 복구와 비교 가능한 조건의 전후 작업을 검증해야 합니다.
   기본 드라이버에서만 측정한 연산 모드 비율이나 상태 증거 없는 속도 향상은
   언락을 입증하지 않습니다.

현재 증거는 펌웨어 구조, BAR 형식, 속성 마스크 및 일관된 두 이미지 ROM
체인을 확인합니다. 실제 해제, 콜드 상태 또는 트랜잭션 조건을 만족하지는
않습니다. [여섯 번째 실제 실행](AD104-SIXTH-RESULT.ko.md)에서는 구현된 실시간
지문/토폴로지 일관성 검사를 통과했습니다. [일곱 번째 실제 실행](AD104-SEVENTH-RESULT.ko.md)은
예상한 EDID 해제, 이후 실제 키보드 입력 및 이번 실행의 Windows 복귀도 확인했습니다.
PCI command는 `0007`이며 BME는 켜져 있습니다. 소비자 관계 하나의 전이이며 전체
디스플레이 스택이나 PCI 소유자 해제는 아닙니다. [텍스트 드라이버 분석](AD104-TEXT-LIFECYCLE.ko.md)은
정리 중 조건부 GOP SetMode 호출을 확인했습니다. EDID 테스트의 대상만 바꾸면
중요한 사후 조건을 빠뜨리게 됩니다. 같은 질의나 사전 검사를
반복할 필요는 없습니다. 향후 실제
해제 테스트에서는 디스플레이/입력 손실 및 Windows 복귀 실패 가능성을 명시하고
시뮬레이션만 한 복구를 보장해서는 안 됩니다.

## Unlock 입증까지 남은 단계

| 단계 | 현재 증거 |
| --- | --- |
| 정확한 식별 정보, 소유 관계 및 실시간 탐색 | 관측 완료; EDID 전이도 입증 |
| 남은 텍스트/GOP 소비자와 PCI 소유권 해제 | 다섯 단계 해제 입증; 포인터 관계 두 개만 남음 |
| 제한적 디코딩 활성화와 cold-entry/보호 메모리 허용 조건 | 활성화 및 실제 읽기 입증; 참조 SS1/VGA_BASE 차이는 미해결 |
| PC별 unlock 트랜잭션과 독립적인 상태 재확인 | 실행하지 않음 |
| Windows 복구와 통제된 기본/unlock 후 작업 | 18차 캡처 후 디코딩 비활성화로 직접 복귀; unlock 후 작업 없음 |

[로드맵](ROADMAP.ko.md)은15/26개 완료(58%)를 셉니다. 각 항목 난이도는 달라
체크리스트 완료율일 뿐 unlock 확률·시간·남은 부팅 횟수가 아닙니다. Cold-entry나
변경 불가능한 하드웨어 제한이 실행을 막을 수 있습니다. 다음 작업은 참조 프로필 복사나
콜백 성공만이 아니라 기록된 ROM·허용 조건 차이를 근거로 진행합니다.

[이슈54 검증과 절차 수정](ISSUE54-VALIDATION.ko.md): 고정 소스/보고 차이, 주장 범위와 읽기 전용 결과 요약. 스테이징된31차는 그대로 유지한다.
