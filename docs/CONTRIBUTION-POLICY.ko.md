# 기여 수용·작업 가이드라인

[English](CONTRIBUTION-POLICY.en.md)

개발 우선순위는 공통 언락·진단 코드와 사용자 로컬 프로필 생성·검증 도구의 개선입니다.
호환성 제보는 환영하지만, 제보 접수가 유지관리자의 장비별 포팅·실험·지원 약속은 아닙니다.

## main에 수용할 변경

| 기여 내용 | 기본 판단 |
|---|---|
| 재현 가능한 버그·안전성 수정 | 관련 회귀 검증과 함께 검토 |
| 공통 진단·프로필 생성·검증·복구 개선 | 재사용 가능한 변경과 실패 경로 검토 |
| 새로운 토폴로지·아키텍처 지원 | 경계가 명확한 공통 구현·근거·대표 fixture 검토 |
| 프로젝트 문서·벤치마크 개선 | 필요성·재현성·유지보수 비용 검토, 기존 도구 재사용 |
| 다른 보드·BIOS·카드용 상수나 하드코딩 분기만 추가 | 제보로 기록하고, 검토된 절차가 허용하면 로컬 프로필 사용 |
| 재사용할 코드 변경 없는 성공 사례 | 비식별 호환성 자료로 보관, 코드 머지 불필요 |
| 구현 복제·광범위한 운영 도구 묶음·대량 원시 로그 | 분리·범위 축소 요청 또는 수용 거절 |
| 특정 장비를 통과시키기 위한 검사 삭제·완화 | 정당한 공통 설계와 음성 테스트 확보 전 보류 |

장비 한 대에서도 공통 결함이나 새로운 기능을 발견할 수 있습니다. 공통 가치와 근거로
판단하며, 수정을 제안하기 위해 여러 장비를 소유할 필요는 없습니다. 공통 수정과 장비별
데이터는 분리합니다.

## 장비별 데이터와 예외

메인보드·BIOS·VBIOS마다 production 프로필을 계속 추가하지 않습니다. 생성된 파티션 설정,
프로필 헤더와 원시 capture는 로컬에 둡니다. 소스·빌드 식별, 관련 관측, 테스트 조건과
한계는 짧은 비식별 이슈로 공유합니다. 공통 변경의 설명·재현에 필요하다면 작은 검토된
근거 요약을 해당 변경에 포함할 수 있습니다.

현재 [로컬 프로필 절차](NEW-MACHINE.en.md)는 [검토된 범위](../research/profile/proven.json)에
제한되며 만능 설치기가 아닙니다. 범위 밖 장비는 연구 자료로 제안하고 검사를 우회하거나
상수를 추정하거나, 이미 안전하게 프로필을 생성할 수 있다고 안내하지 않습니다.

기존 고정 프로필은 참조 구성으로 보존합니다. 새 고정 참조 프로필은 공통 기능·참조 시험에
필요한 이유와 기존 로컬 프로필 형식으로 표현할 수 없는 이유, 유지보수 영향을 명시한
유지관리자의 별도 결정이 있어야 합니다. 한 장비의 부팅 성공만으로 예외를 인정하지 않습니다.

## 실행·머지 전 검토

1. 해결할 공통 문제와 필요한 최소 변경을 확인합니다. 독립적인 연구 문서·벤치마크·진단·
   장비 제어는 분리하고 의존 PR을 명시해 기반부터 검토합니다.
2. 기여자 코드를 실행하기 전에 전체 diff·의존성·실행 경로를 읽습니다. 다운로드·외부 통신·
   파일 생성·관리자 동작·바이너리·출처·라이선스를 확인합니다. 작성자가 제공한 테스트·hash는
   검토 자료이며 진위가 독립적으로 확인됐다는 뜻은 아닙니다.
3. 정확한 장비·펌웨어·코드 fingerprint, ownership, MMIO/PCI, DMA, cleanup 검사를 보존합니다.
   일반화에는 명확한 경계와 음성 테스트가 필요하며 보드별 우회나 일괄 허용 flag로 대체하지 않습니다.
4. 변경에 맞는 검사를 실행하고 미실행 범위를 적습니다. 호스트 모의 시험과 합성 빌드는
   장비 안전·지원을 입증하지 않습니다. [검증 기록](VALIDATION.ko.md)에 따라 진단·transaction·
   Windows 복구·성능 근거를 구분합니다.
5. **머지 / 분리 요청 / 근거 요청 / 보류·거절 / 자료로만 기록** 중 판단을 내립니다.
   공통 이점, 근거, 남은 위험과 유지보수 비용을 설명합니다. 머지 권고가 EFI 실행 허가는 아닙니다.

검토·구현 요청은 댓글 게시·이슈 종료·다른 기여자의 Draft 해제·PR 머지 권한을 만들지 않습니다.
에이전트는 해당 동작에 프로젝트 소유자의 명시적인 승인을 받습니다. 일반적인 작업 계속 요청은
사전에 요구된 게시·머지 승인을 대체하지 않습니다.

## 커뮤니티와 유지관리

중요한 결과·재현 보고·검토·결정은 GitHub 이슈·PR에 남깁니다. Discord는 대화·작은 발견·
협업 조율에 사용하고 유의미한 내용은 GitHub에 요약합니다. 유지관리자가 모든 채팅에서
결정을 추출하거나 장비별 실시간 지원을 제공할 책임은 없습니다.

기존 동작의 회귀·안전 문제 → 작은 공통 수정·선행 PR → 범위가 명확한 새 기능·연구 순서로
검토합니다. 도착 순서대로 수용을 약속하지 않고 감당할 수 있는 대기열을 유지합니다.
inventory만 있는 제보는 구현 약속 없이 자료로 보관할 수 있습니다. 기존 PR도 개별 내용으로
판단하며 정책 변경만으로 일괄 종료하거나, 분류를 위해 새 하드웨어 실험을 요구하지 않습니다.
