# 새 장비의 LOCAL 프로필

[English — 전체 절차](NEW-MACHINE.en.md) | [구성별 결과](CONFIRMED-SETUPS.ko.md)

기존 고정 프로필 6개만이 모든 성공 구성을 뜻하지는 않습니다. 다른 장비는
자신의 읽기 전용 캡처에서 LOCAL 헤더를 생성할 수 있습니다. 이 헤더는
서브시스템, PROM, BAR, PCI 경로, 콘솔 토폴로지 및 드라이버 코드를 그 장비에
고정하며 커밋하거나 다른 PC에서 재사용하지 않습니다. 이 페이지는 현재
허용 범위와 절차의 한국어 요약입니다. 전체 명령/준비/복구 설명은 위 English
문서를 함께 읽으세요. 이 문서를 읽는 것만으로 새 하드웨어 실행을 요청하지 않습니다.

## 현재 허용하는 PCI / 칩 / 메모리 조합

| GPU PCI ID | 칩 | 메모리 레지스터(MiB) | NVIDIA GOP 범위 |
|---|---|---|---|
| `2204 / 2203` (3090 / 3090 Ti) | `b72000a1` GA102 | `6000 / 5ff4` | 기존 검증 코드 |
| `220a` (3080 12 GB) | `b72000a1` GA102 | `3000` | 기존 `60010` 코드만 |
| `2487` (3060 12 GB) | `b74000a1` GA104 | `3000` | `60010` |
| `2484` (3070 8 GB) | `b74000a1` GA104 | `2000` | `60009` |
| `24c9` (3060 Ti LHR) | `b74000a1` GA104 | `2000` | `60015` |
| `2504` (3060 12 GB) | `b76000a1` GA106 | `3000` | `60010` |

정확한 버전/텍스트 해시 조합은 [proven.json](../research/profile/proven.json)에
있습니다. 각 행은 결합된 조건이며 ID·칩·메모리를 독립적으로 섞을 수 없습니다.
특히 3080 10 GB/LHR, 3080 Ti, GA107 노트북, Ada 및 Turing은 이 표에서
허용하지 않습니다. 다른 프로젝트나 비공개 포트의 성공은 별도로 기록합니다.

## 단계와 근거

1. 현재 BIOS, 디스플레이 경로 및 장비 상태를 기록합니다. 별도 완전 종료로
   수집한 일치하는 완전한 읽기 전용 캡처가 최소 두 개 필요합니다.
2. 생성기는 칩/PCI/메모리/클래스, 전원 초기 상태, PROM, 전체 GPU 경로,
   지원 콘솔 관계와 드라이버 코드를 검사합니다. 대상은 하나의 NVIDIA
   디스플레이 컨트롤러여야 하며 대상이 유일한 물리 GOP를 소유해야 합니다.
   알려진 경로 없는 AMI 집계 GOP는 명시된 검사를 만족해야 합니다.
3. 메모리 디코드는 켜지고 BME는 꺼져야 합니다. PciIo 캐시와 실제 PCI
   명령 비트의 일치가 필요합니다. 다른 장비의 사전 교정 코드를 복사해
   이 조건을 우회하지 않습니다.
4. 자신의 PROM/캡처/펌웨어 자산과 생성된 헤더로 현재 호스트 검사를
   실행합니다. 필요한 거부 검사도 예상 종료 코드와 일치해야 합니다.
5. 새 소스나 헤더는 이전 검사 결과를 무효화합니다. 빌드/복사는 실기기
   성공이 아닙니다. 잠금 해제 USB의 부팅은 자동 트랜잭션을 시작할 수
   있으므로 읽기 전용 진단과 구분하고 해당 절차의 위험/복구 경계를 확인합니다.

[#73의 3080 12 GB 근거](../evidence/b550-3080-12gb-local/README.ko.md)는
Windows 진입과 HDMI 복구를 보고하지만 DP 모니터 재연결이 필요했습니다.
이번 통합은 합성/컴파일/RAM 모의 검증이며 최신 소스의 추가 실기기 실행이 아닙니다.

고정 프로필이 없더라도 LOCAL이 이미 그 정확한 조합을 처리하면 새 메인보드
선택기를 추가할 필요가 없습니다. 반대로 캡처/소스/펌웨어/인계 근거가 빠진
보고만으로 상수를 추정해 실행 가능한 프로필을 만들지 않습니다.
