# 유지관리 담당 영역과 인터페이스 검토

[English](MAINTAINER-WORKFLOW.en.md) | **한국어**

합의한 담당 영역을 작업 절차로 정리합니다. 공유 인터페이스 변경에는 두
유지관리자의 검토가 필요하며, 이 문서가 검토 완료를 의미하지는 않습니다.
구현은 [프로젝트 보드](https://github.com/users/impacifist/projects/5)에서 추적합니다.

| 영역 | 담당 | 현재 인터페이스 |
|---|---|---|
| 언락 순서, 하드웨어 허용 조건과 프로필 | @impacifist | `internal-boot/unlock/`, `research/profile/proven.json`, 생성 프로필 헤더/보고서와 픽스처 결합 |
| 드라이버 해제, 복구와 Windows 인계 | @impacifist | `internal-boot/boot/`, PCI 상태 계약, 거부/계속 실행 경계 |
| 설정, 빌드 실행과 기여자 도구 | @DeclanFrampton | `research/profile/new-machine.ps1`, 빌드/스테이징 래퍼, `tools/` |
| 증거 도구, 호스트 검사, 패키징과 EN/KO 안내 | @DeclanFrampton | 캡처 파서, 테스트 보고서, 매니페스트, 문서와 릴리스 자동화 |

디렉터리만으로 담당을 독점하지 않습니다. 파서나 빌드 래퍼도 핵심 불변 조건을
검증할 수 있으므로 다음 계약을 바꾸면 상호 검토를 요청합니다.

## 보존할 계약

- **캡처와 언락 분리:** 캡처 전용 실행은 프로필 생성, 펌웨어 자산 재현 테스트,
  언락 패키징/스테이징 전에 종료합니다. 일반 프로브의 진단 전용 컴파일 정의를
  유지합니다. 프로브 부팅은 사람이 지켜보는 하드웨어 작업이며 호스트 테스트나
  복구 보장이 아닙니다.
- **허용 조건:** `proven.json`, 프로필 상수, 이미지 해시와 토폴로지 검사는 핵심
  담당자의 검증 경계입니다. 도구는 거부를 표시하며 경고로 낮추거나 우회 옵션을
  만들지 않습니다.
- **증거:** 원본 캡처를 보존합니다. 파일 완전성, 파서 통과, 호스트 재현,
  Windows 복귀와 측정된 언락 효과는 서로 다른 증거입니다.
  `capture-complete=1`은 호환성이나 언락의 증명이 아닙니다.
- **스키마/버전:** 진단 키, 프로필 JSON, 매니페스트나 호스트 테스트 증거 변경
  전에 소비자를 조사합니다. 생성기, 파서, 픽스처와 EN/KO 설명을 함께 갱신합니다.
  알 수 없거나 호환되지 않는 입력은 명시적으로 거부하고 과거 증거를 조용히
  재해석하지 않습니다. 이 합의는 새로운 전역 스키마 버전을 도입하지 않습니다.
- **빌드/스테이징:** 사전 검사는 호스트 도구만 확인합니다. 설치, 영구 PATH
  변경, USB 파일 스테이징이나 부팅 설정 변경을 하지 않습니다. 스테이징은 기존
  대상 검사와 로더 백업을 유지하는 명시적 작업입니다.
- **릴리스:** 패키지 검증은 하드웨어 지원 검증이 아닙니다. 릴리스 전에 핵심
  담당자가 정확한 하드웨어 증거와 지원 범위를 검토합니다.

## 작업 절차

카드마다 한 명의 담당자를 두고 구현 전에 의존성을 기록합니다. 최신 main에서
분리된 브랜치를 만들고, 진행 중인 PR과 겹치는 공유 파일 이동을 피합니다.
기존 이슈와 실험을 연결하고 경쟁 구현을 만들지 않습니다. PR은 한 가지
인터페이스 변경에 집중하고 실제 수행한 검사와 남은 불확실성을 기록합니다.
구체적인 결과가 준비되면 Review로, 수락 기준과 필요한 검토 및 통합이 끝나면
Done으로 옮깁니다.

첫 도구 변경은 호스트 전용 사전 검사와 명시적인 캡처 전용 경로입니다.
입증된 하드웨어 범위를 넓히거나 새 하드웨어 실험을 승인하지 않습니다.
기존 AD104와 EVGA 연구는 각자의 증거와 테스트 승인을 유지합니다.
