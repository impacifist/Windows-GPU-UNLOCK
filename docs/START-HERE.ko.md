# PC를 확인하고 결과를 공유하세요

[English](START-HERE.en.md) · **한국어** · [프로젝트로 돌아가기](../README.ko.md)

**언락을 시도하지 않아도** 기여할 수 있습니다. Windows 인벤토리부터 시작하거나 이미 보유한 캡처 파일을 검사하세요.

> [!TIP]
> **처음이라면 1번을 선택하세요.** 인벤토리 보고에는 USB, 컴파일러, 펌웨어 파일, 관리자 터미널이나 BIOS 변경이 필요하지 않습니다.

| 보유한 항목 | 시작 위치 | 얻는 결과 |
| :--- | :--- | :--- |
| Windows PC만 있고 캡처 파일이 없음 | [**1 · PC 정보 확인**](#1--pc-정보-확인) | 보고할 하드웨어/드라이버 정보 |
| 자신의 PC에서 얻은 `DIAGnn.TXT`, `IMGnn.BIN`, `PROM.BIN` | [**2 · 기존 파일 검사**](#2--기존-파일-검사) | 이유가 포함된 오프라인 결과 |
| 새로운 EFI 캡처 수집 요청 | [**3 · 캡처 계획**](#3--캡처-계획) | 별도의 입회 부팅 절차 |

## 시작 전 · 프로젝트 폴더 열기

1. [프로젝트 페이지](https://github.com/impacifist/Windows-GPU-UNLOCK)에서 **Code → Download ZIP**을 선택합니다.
2. ZIP을 오른쪽 클릭하여 **모두 압축 풀기**를 실행합니다. `README.md`, `tools`, `research`가 있는 폴더를 엽니다. ZIP 미리보기 안에서 실행하지 마세요.
3. 파일 탐색기 주소 표시줄에 `powershell`을 입력하고 **Enter**를 누릅니다. 해당 폴더에서 일반 터미널이 열립니다.
4. Python을 확인합니다.

   ```powershell
   python --version
   ```

아래 두 옵션에는 **Python 3.10 이상**을 사용하세요. Store가 열리거나 명령을 찾지 못하거나 이전 버전이면 [python.org](https://www.python.org/downloads/windows/)에서 설치한 뒤 터미널을 닫고 다시 엽니다. `py`를 사용하는 설치라면 `py -3 --version`을 확인하고 아래 명령의 `python`을 `py -3`으로 바꿀 수 있습니다. 설치를 원하지 않으면 보고 양식에 하드웨어 정보를 직접 입력해도 됩니다.

## 1 · PC 정보 확인

아래 명령 하나를 터미널에 붙여 넣고 Enter를 누릅니다.

```powershell
python -I .\tools\collect_compatibility.py
```

Windows 하드웨어 정보를 읽어 출력합니다. 언락 실행, 설정 변경, 펌웨어 쓰기나 업로드를 하지 않습니다. `{`로 시작하고 `hardware`, `assessment` 같은 항목이 있는 JSON 텍스트가 표시됩니다.

**정상 결과:** `assessment.status`는 `not-assessed`, `can_unlock`은 `false`입니다. 동작 보고가 있는 카드도 동일합니다. 인벤토리는 PC를 설명할 뿐 언락 호환성을 인증하지 않습니다. 일부 항목이 누락되어도 수집된 내용을 보고하고 나머지를 직접 입력할 수 있습니다.

**다음:** 출력을 검토하고 [결과 공유](#결과-공유)로 진행합니다. Windows 내 검사는 끝났으며 EFI 부팅이 필요하지 않습니다.

## 2 · 기존 파일 검사

**자신의 PC**에서 얻은 파일을 원래 캡처 폴더에 함께 둡니다. 예제의 `D:\RTX3090-UNLOCK`을 실제 폴더 경로로 바꾸세요. 이 과거 폴더 이름은 다른 카드에도 사용되며 GPU 모델을 식별하지 않습니다.

```powershell
python -I .\research\profile\check-compatibility.py "D:\RTX3090-UNLOCK" --json --lang ko
```

로컬 파일만 읽습니다. 실행 중인 GPU 검사, 캡처 파일 실행, 언락 프로필 생성이나 업로드는 하지 않습니다. 컴파일러도 필요하지 않습니다. 파일 누락도 보고 가능한 결과입니다. 빈 항목을 채우려고 다른 사람의 캡처를 내려받지 마세요.

| 결과 | 쉬운 설명 | 보고할 내용 |
| :--- | :--- | :--- |
| `candidate` | 이 경로의 오프라인 검사를 통과함 | 결과 공유; **언락 승인 아님** |
| `needs_data` | 필요한 데이터가 없음 | 누락된 항목 |
| `outside_scope` | 이 자동 경로가 기록된 구성을 허용하지 않음 | 거부 이유; 다른 경로는 다를 수 있음 |
| `invalid_data` | 파일 또는 관찰 내용을 허용할 수 없음 | 이유를 공유하고 원본 보존 |
| `error` | 검사기를 제대로 불러오지 못함 | 오류와 받은 소스 버전 |

후보가 아닌 결과의 종료 코드 `2`는 예상된 동작이며 프로그램 충돌을 뜻하지 않습니다. 제한 사항과 비교 도구는 [검사기 상세 안내](CHECK-COMPATIBILITY.ko.md)를 참조하세요.

## 결과 공유

1. [기존 이슈](https://github.com/impacifist/Windows-GPU-UNLOCK/issues)에서 이전 보고를 검색합니다. 같은 머신과 조사라면 기존 이슈를 갱신합니다.
2. 새 보고라면 [호환성 보고 양식](https://github.com/impacifist/Windows-GPU-UNLOCK/issues/new?template=compatibility.yml)을 엽니다. 이슈 제출에는 GitHub 계정이 필요하지만 위 검사는 계정 없이 사용할 수 있습니다.
3. 1번을 실행했다면 **검토한 인벤토리 출력**을 인벤토리 항목에 붙여 넣습니다. 2번을 실행했다면 해당 JSON을 **Offline compatibility report**에 넣습니다. 인벤토리를 수집하지 않았다면 하드웨어 정보를 직접 입력합니다. 두 보고는 형식이 다르므로 구분합니다.
4. 보드/BIOS, 실제 카드 모델, 모니터 케이블 연결 위치를 적습니다. 미상도 유효한 답입니다. EFI를 실행하지 않았는지, 기존 실행 후 실제 Windows/화면 결과와 수동 전원 종료가 있었는지 명시합니다.
5. 소스 커밋을 알면 적고, 모르면 main ZIP 사용 여부와 다운로드 날짜를 적습니다. 실패했다면 명령과 오류 텍스트를 포함합니다.

> [!IMPORTANT]
> 검토한 **텍스트 보고서**를 공유하세요. `PROM.BIN`, `IMGnn.BIN`, 펌웨어 자산이나 원시 시스템 덤프를 올리지 마세요. 개인 경로, 일련번호, UUID, 복구 키와 공개하고 싶지 않은 내용은 제거합니다. 자동 업로드는 없습니다.

<details>
<summary><strong>선택 사항 · 표시된 보고서를 텍스트 파일로 저장</strong></summary>

터미널의 보고서를 메모장에 복사하고 새 이름으로 저장하면 제출 전에 검토하기 쉽습니다. 기존 파일을 덮어쓰지 않도록 주의하세요. 검토한 텍스트를 양식에 직접 붙여 넣어도 되며 파일 저장은 필수가 아닙니다.

</details>

## 3 · 캡처 계획

EFI 캡처는 Windows 시작 전에 정보를 수집합니다. 위의 **Windows 인벤토리와 다른 작업**입니다. GPU 쓰기를 하지 않는 진단도 멈추거나 Windows로 돌아오지 못하여 수동 전원 종료가 필요할 수 있습니다. 이슈 양식을 채우려고 보안 기능을 끄거나 펌웨어를 부팅하지 마세요.

진행하기로 했다면 [새 머신 캡처 안내](NEW-MACHINE.ko.md)의 전제 조건과 복구 한계를 먼저 읽으세요. 그 문서에는 이후 프로필/빌드 단계도 포함됩니다. 증거 수집만이 목적이면 **캡처 경계에서 멈춥니다**. 호환성 보고에 언락 실행은 필요하지 않습니다.

안내형 `Start-Capture.cmd` 런처는 [PR #112](https://github.com/impacifist/Windows-GPU-UNLOCK/pull/112)에서 개발 중이며 이 main 스냅샷에는 없습니다. 다운로드한 main ZIP에서 해당 파일을 찾을 수 있다고 가정하지 마세요.

---

**언락 실행 안내를 찾고 있나요?** 먼저 [정확한 지원 구성](COMPATIBILITY.ko.md)을 확인하세요. GPU 이름 일치, 인벤토리 출력 또는 `candidate`만으로 새 머신이 적격해지지는 않습니다.
