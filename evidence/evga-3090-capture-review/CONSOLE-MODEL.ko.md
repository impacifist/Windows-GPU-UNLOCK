# 콘솔 의존성 모델 및 서비스 초기화

[English](CONSOLE-MODEL.en.md) | [한국어](CONSOLE-MODEL.ko.md)

## 변경 사항

`research/profile/evga3090-console-model.py`는 선택된 소유 기록 5개와 제거 순서 3개를 표현하는 CPU 전용 모델입니다. 순서는 텍스트 분배 역할, 가상 GOP 텍스트 소비자 IMG16, 그래픽 분배 역할입니다. 이는 기호 역할이며 인증된 소스 모듈 이름이 아닙니다. 누락/중복/예상 밖 기록, 1이 아닌 열기 개수, 다른 순서, 콜백 실패, 불완전한 호출 후 관찰, 변경되지 않거나 예상과 다른 그래프는 거부합니다. 성공해도 쓰기 권한이나 언락을 허용하지 않습니다. 명령어 에뮬레이션 또는 드라이버 안전성 증명이 아닌 가정 모델입니다.

두 저장 로그의 GOP/SimpleTextOut 관계를 기호 역할로 정규화한 결과 각각 정확히 5개 관계 집합과 일치했습니다. [저장 결과](console-model-results.json)는 입력 해시와 모델 밖 EDID 관계를 기록합니다. 모델의 제거는 예상 관계 변화를 합성하며 실제 Stop 이후 관찰 결과가 아닙니다. 실제 펌웨어 호출은 없었습니다.

새 회귀 사례 9개, 전체 Python 테스트 78개가 통과했습니다. 저장소 루트에서 실행하세요.

```powershell
python -m unittest discover -s research/profile -p 'test_evga3090_console_model.py'
```

## 서비스 테이블 초기화 근거

표준 UEFI x64 진입 규약에서 RDX는 시스템 테이블이고 BootServices는 오프셋 0x60입니다. 기준은 저장소의 deps/edk2/MdePkg/Include/Uefi/UefiSpec.h입니다.

- IMG13: 진입 RVA 0x350의 0x364는 [RDX+0x60]을 읽고 0x36b는 0x6230에 저장합니다. 추가 초기화 0xb11/0xb15는 같은 방식으로 Stop에서 사용하는 전역 0x6240을 설정합니다.
- IMG16: 진입 0x350은 0x37c 및 0x444를 호출합니다. 0x386/0x38a는 [RDX+0x60]을 0x3810에 저장하며 0x45e/0x462는 Stop 전역 0x3820을 설정합니다.
- IMG17: 진입 0x370은 RDX를 바꾸지 않고 0x424를 호출합니다. 0x42e/0x432는 [RDX+0x60]을 Stop 전역 0x1e60에 저장합니다.

Stop 간접 호출을 표준 Boot Services로 해석하는 근거가 강화되었습니다. IMG13에는 서로 다른 서비스 전역이 2개 있으며 Stop 전역 초기화의 완전한 도달 경로와 인수 검토가 남아 있습니다. 런타임 덮어쓰기, 헬퍼 의미, 간접 콜백, 객체 수명은 아직 완전히 검증하지 않았습니다. 따라서 하드웨어 허용 근거는 아닙니다.

## 별도 물리 GOP 의존성

두 로그에는 물리 GOP의 EDID Discovered 프로토콜을 IMG07이 BY_DRIVER, count 1로 연 기록도 있습니다. 바인딩 식별자는 c7a7030c-c3d8-45ee-bed9-5d9e76762953입니다. 선택된 5개 관계 모델은 이를 제거하지 않고 남은 작업으로 표시합니다. NVIDIA 부모/자식 관계도 범위 밖이므로 전체 그래프의 정지를 주장하지 않습니다.

다음 단계는 EDID/NVIDIA 경로, 헬퍼/간접 대상과 집계 콘솔 객체 수명 검증입니다. 이후 모델 확장 또는 새로운 참석형 EFI 테스트를 제안합니다. 기존 파일 분석을 위해 기여자가 새 캡처나 재부팅을 할 필요는 없습니다. 기존 프로필 허용 거부는 유지합니다.
