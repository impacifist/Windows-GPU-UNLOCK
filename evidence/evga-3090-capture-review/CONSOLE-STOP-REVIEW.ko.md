# EVGA3090 콘솔 Stop 검토

[English](CONSOLE-STOP-REVIEW.en.md) | [한국어](CONSOLE-STOP-REVIEW.ko.md)

업로드된 AMD64 로드 이미지의 정적 명령어를 Capstone으로 확인했습니다. 펌웨어 실행, 드라이버 메서드 호출, GPU 접근, USB 상태 변경은 없었습니다. Movian은 2026년 10월 27일 21:28 Discord에서 지문 검사를 재현했고 21:29 브랜치 업데이트에 문제가 없었다고 보고했습니다. 표시된 캡처 및 코드 해시는 [저장 결과](console-code-test-results.json)와 일치합니다.

## 확인한 동작

주소는 로드 이미지의 RVA입니다. 일반 디스크 PE의 파일 오프셋이 아닙니다. 기존 코드 해시와 식별자를 사용하며 새 프로필이나 하드웨어 실행 권한을 만들지 않습니다.

- IMG13 Stop은 0x104c입니다. 0x1078에서 자식 수를 검사하고 0이면 0x107d에서 성공을 반환합니다. 따라서 성공만으로 콘솔 연결 해제를 입증할 수 없습니다.
- IMG13의 0x1084는 자식 수 1을 요구하고, 0x108e는 버퍼를, 0x1097–0x10a1은 저장된 전역 자식 핸들과의 일치를 요구합니다. 잘못된 입력은 0x11eb에서 EFI_INVALID_PARAMETER로 처리됩니다.
- IMG13의 0x10db 및 0x10fd는 RVA 0x5920의 SimpleTextOut GUID로 서비스 테이블 슬롯 0x120을 호출합니다. 각 호출 직후 상태 분기는 없습니다. 이후 0x4db0, 0x4200 헬퍼와 슬롯 0x48, 0x150 호출도 있습니다. 전체 부작용은 아직 검증하지 않았습니다.
- IMG17 Stop은 0x88c입니다. 자식 수 0 경로는 전역 개수와 버퍼를 검사하며 슬롯 0x48 호출과 전역 상태 초기화를 수행할 수 있습니다. 완전한 무동작이라고 볼 수 없지만 관찰된 컨트롤러별 제거 경로를 통과하지는 않습니다.
- IMG17의 0x8f4는 자식 수 1, 0x8fa는 버퍼, 0x8ff–0x909는 전역 자식 핸들과의 일치를 요구합니다. 컨트롤러 목록 검색도 수행하며 잘못된 입력은 0x922에서 EFI_INVALID_PARAMETER로 처리됩니다.
- IMG17의 0x95d 및 0x97f는 RVA 0x1c60의 GOP GUID로 슬롯 0x120을 호출합니다. 바로 다음 상태 확인 없이 목록 제거, 카운터 감소, 슬롯 0x48 호출이 이어집니다. 반환값만으로 해제를 검증할 수 없습니다.
- IMG17은 구성원이 남으면 0xbc0 헬퍼와 슬롯 0x88을 호출하고, 마지막 구성원을 제거하면 0x156c 헬퍼 및 모드/전역 상태 변경 경로로 진행합니다. 마지막 구성원 경로는 별도 검토가 필요합니다.

저장소의 deps/edk2/MdePkg/Include/Uefi/UefiSpec.h에 있는 표준 x64 EFI_BOOT_SERVICES 레이아웃에서 슬롯 0x48은 FreePool, 0x88은 ReinstallProtocolInterface, 0x120은 CloseProtocol, 0x150은 UninstallMultipleProtocolInterfaces입니다. 이는 조건부 해석이며 실제 간접 호출 대상 테이블의 출처까지 입증한 것은 아닙니다. GUID 바이트는 직접 확인했습니다. 그래픽 헬퍼 0x156c에는 전달된 인터페이스의 오프셋 0x10을 통한 간접 호출이 있으며 동적 대상은 미검증입니다. 화면 유지나 복구 안전성을 주장할 수 없습니다.

## 다음 단계

아직 EFI 수명주기 테스트를 준비하지 않습니다. 서비스 테이블 출처, 헬퍼 대상, 집계 콘솔 생성자와 남은 소비자, 마지막 구성원 분기를 먼저 검증해야 합니다. 이후 예상하지 못한 소비자를 거부하고 각 연결 변화와 객체 수명을 확인하는 오프라인 모델을 만듭니다. 합성 모델은 하네스 가정만 검증하므로 실제 하드웨어 테스트에는 별도 명시적 위험 승인이 필요합니다.

기존 자동 토폴로지 거부는 유지합니다. 언락, 리셋, 펌웨어 업로드/실행, GPU 레지스터 접근은 하지 않았습니다. 검토 중 기여자가 추가로 재부팅하거나 작업할 필요는 없습니다.

## 추가 가상 GOP 소비자

가상 GOP에는 IMG16의 count-1 BY_DRIVER 소유자도 있습니다. 식별자는 43e7abdd-e352-4cfb-a230-4cdc1d350e5c, Stop RVA는 0xb2c입니다. 이전 9개 연결 검사와 두 드라이버 지문 검사는 이 세 번째 드라이버를 검증하지 않았습니다. 성공 결과는 제한된 범위 내에서 유효하지만 완전한 해제 계획은 아닙니다.

IMG16은 0xb6b에서 RVA 0x20b0의 SimpleTextOut GUID 및 GET_PROTOCOL 속성 2로 슬롯 0x118을 호출합니다. 0xb9d에서 슬롯 0x120, 0xbd5에서 SimpleTextOut과 e1e4a857-c970-4075-a4da-e9c41b69adfc GUID를 사용해 슬롯 0x150을 호출합니다. 두 번째 GUID의 프로토콜 이름은 여기서 지정하지 않습니다. 0xbdb–0xbde는 제거 결과를 검사합니다. 이후 0xbf8에서 RVA 0x20e0의 GOP GUID로 슬롯 0x120을 호출하고 슬롯 0x48 호출 3개를 수행합니다. 표준 테이블 해석상 GOP를 소비하여 텍스트 인터페이스를 제공하고 제거하는 역할을 시사하지만 테이블 출처와 객체 검증 전에는 확정할 수 없습니다.

따라서 의존성 연결에는 이전에 지문을 확인한 두 바인딩 외에 중간 GOP 소비자가 포함됩니다. IMG16과 그 텍스트 소비자를 먼저 검증해야 합니다. 이는 오프라인 분석을 위한 제안 순서이며 실제 하드웨어 실행 또는 승인된 시퀀스가 아닙니다.

IMG16 실행 섹션 지문: 7680바이트, SHA256 e5e68f0856c6e932da9bf3c680bac955dbf180eb083da78b64007388d89e24a7. 저장 이미지 관찰이며 인증된 드라이버 출처는 아닙니다.
